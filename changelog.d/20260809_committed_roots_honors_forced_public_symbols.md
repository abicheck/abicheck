### Fixed

- **`compare --post-manifest` combined with `--public-symbol`/`force_public_symbols` and header scoping now honors the forced-public widening overlay when scoping stdlib direct-reference roots** (Codex review, fresh evidence). `post_processing._run_allowlist` already keeps a `Change` on a forced-public symbol in-surface as a widening overlay when header scoping is also on, but `contract_pipeline.build_contract_stage`'s own `committed_roots` — threaded into `directly_referenced_stdlib_type_spellings` to scope which declarations may seed a stdlib direct-reference root under an active manifest — never consulted `force_public_symbols` at all. An uncommitted-but-forced-public function referencing a stdlib type (e.g. `api(std::vector<int>)`) was rejected as a root, so a genuine stdlib layout break under it classified `UNKNOWN_UNRESOLVED` (gate: `NO_CHANGE`) even though the identical comparison without the manifest correctly reports `BREAKING`. `committed_roots` is now widened with `force_public_symbols` whenever a manifest is active, gated on `scope_to_public_surface` to mirror `_run_allowlist`'s own condition exactly — the widening overlay is a header-scoping concept the CLI already warns is ignored under `--no-scope-public-headers`.
