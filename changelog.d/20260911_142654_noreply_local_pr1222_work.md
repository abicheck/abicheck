### Fixed

- **The `check-target` assurance overlay no longer treats a checkout-side
  `compile.frontend: auto` as an explicit value that blocks a sources-root
  `compile.frontend` setting.** `_merge_compile_block` previously classified
  `frontend` under the plain "checkout already set this key" rule, which
  only holds for a genuinely unset field; `frontend`'s own semantic-default
  sentinel (`"auto"`) needed the same "treat as unset" handling
  `cli_options.merge_compile_config` already gives it. A checkout config
  with `compile.frontend: auto` and a distinct sources-root config selecting
  `compile.frontend: clang`/`castxml` now correctly resolves to the
  sources-root's frontend when `check-target` enables the assurance
  overlay's per-field `compile:` merge, matching the real two-stage
  `merge_compile_config()` resolution instead of silently pinning `auto`
  and changing the AST backend, analyzed surface, and findings.
