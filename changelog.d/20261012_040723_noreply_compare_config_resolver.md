### Changed

- **Internal: compare-configuration resolution moved out of the CLI.** `ResolvedCompareConfig`, `resolve_compare_config`, `load_required_symbols` and `resolve_force_public_scope` moved from `abicheck.cli_helpers_compare` to their ADR-061 owner, `abicheck.workflows.compare_configuration`. `cli_compare_helpers._resolve_compare_collect_mode` moved there too, as the public `resolve_compare_collect_mode`, and a new `load_and_resolve_compare_config` reads `.abicheck.yml` and resolves it in one call. They raise `CompareSettingsError`, a `ValidationError`, instead of `click.UsageError`, so the typed API, Action and MCP paths can call them without Click. The CLI turns the error back into the same usage error and exit code 64, so CLI output is unchanged. The old import paths are gone, with no aliases: the `# noqa: F401` re-exports in `frontends/cli/runtime.py`, `frontends/cli/commands/compare.py` and `frontends/cli/commands/dump.py` are deleted, and so are `cli_helpers_compare`'s re-exports of `_canonical_library_key`/`_version_sort_key` (owner: `abicheck.workflows.extraction`), `strip_vendor_hash` (owner: `abicheck.model.binary_naming`) and `_collect_force_public_symbols` (owner: `abicheck.compatibility_evaluation_frontend.collect_force_public_symbols`), as is the delegation-only `cli_compare_helpers._resolve_compare_config` (owner: `frontends.cli.project_config.resolve_project_compare_config`).
