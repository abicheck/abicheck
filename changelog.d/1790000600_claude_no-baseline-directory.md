### Added

- `abicheck compare --no-baseline DIR` audits every library of a candidate release with no baseline -- a directory, a package archive (`.deb`/`.rpm`/`.whl`/`.tar.*`/...), or a multi-artifact stored `ProjectSnapshot` package -- replacing the retired `scan --artifact-set` (one-comparison-product acceptance F-23). Each member is audited exactly as `compare --no-baseline <member>` would audit it; members are discovered by the same resolver a two-sided directory/package `compare` uses and recorded on ADR-065's acquisition record (`--select`/`--select-required`, `.abicheck.yml`'s `scope.on_incomplete`, `release.dso_only`, `release.include_private_dso`; a directory proves nothing about its inventory, a fully extracted archive or an asserting stored package does). `--variant` selects a stored package's variant. One `audit_set` JSON document (`audit_set_report.schema.json`, `audit_set_report_schema_version` 1.0) holds every member's own audit report, member-tagged root `findings`, the `comparison_scope` section and one exit code: the max of every member's axes, `4` for a member whose audit failed, and the scope axes -- a run that audits no member exits `1`. Formats: `json`, `markdown` (default) and `oneline`; `--dry-run` lists the members a run would audit or skip. The PR-comment renderer, `aggregate` and the Action's report reader read the new document as an audit.

### Fixed

- `compare --no-baseline` routed a package archive and a multi-artifact or degraded stored `ProjectSnapshot` package to the single-artifact path: an archive was refused as an unrecognized format, a multi-artifact package failed, and a degraded single-artifact package was audited as if its capture were complete. The operand is now classified by the same classifier two-sided `compare` uses, and every set-shaped operand is audited per member.
