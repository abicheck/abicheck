### Added

- **Opt-in provenance for baseline-set archives** — `actions/stage-baseline` takes `attest: true` and creates a GitHub artifact attestation for the archive it writes (`actions/attest-build-provenance`, pinned by SHA; the job needs `id-token: write` and `attestations: write`) and outputs `attestation-url`. The root Action and `actions/resolve-baseline` take `verify-baseline-attestation: true`, with `baseline-attestation-repo` (default: the current repository) and `baseline-attestation-signer-workflow`, and run `gh attestation verify` on the archive's bytes before anything is extracted. A refused attestation, a wrong signer, and a runner without `gh` all fail closed (the root Action even under dry-run; `resolve-baseline` with outcome `ambiguous` and the new `archive-attestation-verified` output). Setting the repo/signer inputs without verification, or verifying a directory, is a usage error. Defaults are unchanged. `docs/reference/publish-baseline.md` now documents where to pin `expected-archive-digest` so it actually protects the consumer (committed in the consumer repository or a repository variable, never next to the archive).
