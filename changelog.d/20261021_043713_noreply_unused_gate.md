### Changed

- **`unused` vs `not_evaluated` is decided per rule, so `unused_rules: block` can now fire on an ELF-only run** — a configured rule that matched nothing used to read `not_evaluated` whenever any detector of the comparison was refused, which is almost every ELF-only run, so the gate almost never fired. A rule now reads `unused` when at least one detector that can produce one of its change kinds ran, and `not_evaluated` only when none did. A rule with no kind selector can match any kind. The candidate detectors come from a generated map, `abicheck/policy/detector_kind_map.py` (built by `scripts/gen_detector_kind_map.py`, drift-gated by `tests/test_detector_kind_map.py`). On an ELF-only compare a stale symbol-kind `reclassify:` rule now reads `unused` and, under `unused_rules: block` or `--fail-on-unused-rules`, exits `1`; a stale rule scoped to a DWARF-only kind still reads `not_evaluated` and does not trip the gate. Existing `unused_rules: allow` runs keep their exit codes, but the audit's `status` on those rows can change from `not_evaluated` to `unused`. A kind that only a pipeline step emits (not a registered detector), such as `inline_body_changed`, still reads `not_evaluated`.
