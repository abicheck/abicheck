### Fixed

- **A type change to or from an unresolved pointee is reported when its pointer/reference structure alone proves it.** castxml spells an unresolvable pointee as `?*`, `?&` or `const ?`. Since the variable cutover a variable going from `int` to `?*` was only a declined comparison, and a function return or parameter going from `int *` to `?*` was reported as `FUNC_RETURN_CHANGED`/`FUNC_PARAMS_CHANGED` even though the `?` may be `int`. One rule in the new `abicheck/model/type_indirection.py` now decides every such pair for `VAR_TYPE_CHANGED`, `FUNC_RETURN_CHANGED`, `FUNC_PARAMS_CHANGED` and `RETURN_POINTER_LEVEL_CHANGED`/`PARAM_POINTER_LEVEL_CHANGED`: a change is reported only when the known declarator levels cannot describe the same type (`int` -> `?*`, `int &` -> `?*`, `?&` -> `?*`). Compatible shapes (`?*` -> `?*`, `int **` -> `?*`) stay unknown, so no finding is invented.
- `semantic_ir` documents older than version 3 now mark a function's or variable's deprecation, access and alignment facts with a declaration-specific "not recorded" diagnostic instead of the function-signature one.
