### Fixed

- **A removed explicit specialization is now reported as a removed declaration on the castxml route.** castxml's XML gives an explicit specialization its own location, the line of its `template <>` declarator, so the castxml header backend now reads that line and records `explicit_instantiation_fact` = `SPECIALIZATION` (the clang backend already did). Before, the castxml side could not tell a removed explicit specialization from an implicit instance, so a header-graph comparison reported it as an export loss (`func_visibility_changed`) instead of `func_removed`. The extractor generation is 86 (spelling row 86: no stored spelling changes; an older snapshot carries no such fact and reads as no evidence). Explicit instantiations (`extern template`, `template` definitions) are not yet recorded on the castxml route and keep the previous behaviour.
