### Fixed

- **A pull request could accept its own findings through the Action's overlay** — the Action folds a discovered `.abicheck.yml` into an explicit `--config` overlay, and the `acknowledgment.file` key was not stripped, so a records file planted in the checkout loaded as if an operator had named it. The overlay builder now strips `acknowledgment.file` and `acknowledgment.breaks` from a discovered document and rebases a relative `file` against the project root (`action_config_overlay.py`). The CLI's own trust rule was already correct; only the Action path leaked. Use the new `protect-committed-baseline` recipe to gate the records file on pull requests (see `docs/use/acknowledgments.md`).
- **A `symbol` acknowledgment accepted every change on that symbol** — a record naming a symbol without a `change_kind` now fails to load with a `PolicyError`, and a record that matches more than one change in one run is an error rather than a silent double acceptance. An unscoped record and an expired record each print a warning, and an expired record never matches, so its finding gates again. Records written as `symbol:` alone need a `change_kind:` added; use `finding_id:` to name one finding without a kind.
