### Changed

- **Function signature findings now read the canonical IR (ADR-063 6B, function-signature cohort; snapshot schema v57).** `FUNC_RETURN_CHANGED`, `FUNC_PARAMS_CHANGED`, `FUNC_REF_QUAL_CHANGED` and `FUNC_VARIADIC_ADDED`/`FUNC_VARIADIC_REMOVED` are decided in the new `abicheck/compare/function_signature.py` from five facts the `SemanticIR` now carries for every function occurrence (`return_type_spelling`, `parameter_type_spellings`, `parameter_kinds`, `ref_qualifier`, `is_variadic`; `semantic_ir` document version 3, `ProjectSnapshot` section v3). The spellings are the producer's own, so verdicts are unchanged. A pre-v57 snapshot decodes the facts as not collected and the load path fills them from the snapshot's own functions (`abicheck/model/semantic_ir_function_signature.py`), so stored baselines compare exactly as before. A signature fact that is not established on a side is recorded as a declined comparison instead of passing silently.
- **Function qualifier and declaration-fact findings now read the canonical IR too (ADR-063 6B).** The same `semantic_ir` v3 document carries each function's linkage, `noexcept`, `virtual`, `explicit`, hidden-friend status and owner, contract attributes, dynamic exception spec and vtable slot, plus each function's and variable's deprecation, access and (for variables) declared alignment. Every check that compared those values -- `FUNC_LANGUAGE_LINKAGE_CHANGED`, `FUNC_NOEXCEPT_*`, `FUNC_VIRTUAL_*`, `CTOR_EXPLICIT_*`, `HIDDEN_FRIEND_*` (paired and inline), `CALLING_CONVENTION_CHANGED`/`FUNC_CONTRACT_ATTRIBUTE_*`, `FUNC_EXCEPTION_SPEC_CHANGED`, the per-function `TYPE_VTABLE_CHANGED`, `FUNC_DEPRECATED_*`, `VAR_DEPRECATED_*`, `METHOD_ACCESS_CHANGED`, `VAR_ACCESS_*` and `VAR_ALIGNMENT_CHANGED` -- now decides from those IR facts (`abicheck/compare/function_signature.py`, `abicheck/compare/declaration_facts.py`). Each fact keeps the status its producer recorded, so an unestablished linkage/`noexcept`/`virtual` flag is a declined comparison rather than a fabricated change.

- A function's or variable's IR facts are re-projected from its declaration at comparison time, so editing a loaded snapshot's `Function`/`Variable` in place is compared by the edit rather than by the stale copy persisted in its `semantic_ir`.
