### Fixed

- **A calling convention on a function-pointer type is no longer lost** — `void (__attribute__((ms_abi)) *p)(int)` and `void (*p)(int)` read as the same type on every path, so a switch between them compared as `NO_CHANGE` with an exit of 0 (the argument registers differ: `%rcx` against `%rdi`). The header lane restores the convention castxml drops, joined from the clang AST, and the DWARF lane spells a subroutine type with its full signature and convention (`void (*)(int) __attribute__((ms_abi))`), so a DWARF-only callback signature change is reported as well. Clang-built DWARF carries the convention; GCC writes none for `ms_abi`, so a GCC `-g` build can only be checked through its headers. The extractor generation moves to 29; an older baseline's callback spelling is demoted as generation drift, not reported as a break.
