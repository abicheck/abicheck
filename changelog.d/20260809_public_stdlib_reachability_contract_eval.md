### Fixed

- **Contract evaluation (`--contract-evaluation`) now confirms a layout break on a stdlib type a public signature names directly** — previously, a `TYPE_SIZE_CHANGED`/similar finding on e.g. `std::string` or `std::vector<int>` used directly by a public function stayed `UNKNOWN_UNRESOLVED` even though `diff_types.py`'s own `type_reachability.directly_referenced_stdlib_types` evidence is exactly what kept the finding from being filtered as toolchain-internal churn in the first place — the evaluator simply never saw that evidence. `contract_pipeline.build_contract_stage` now computes each side's `type_reachability.directly_referenced_stdlib_type_spellings` once and threads it through to `contract_evaluation.evaluate_change_contract_relevance`, which uses it as a second, independent confirmation source alongside `PublicSurface.public_types` (which deliberately excludes stdlib types as non-ABI-surface). Lowers the shadow contract-evaluator measurement gate's `public`-domain unresolved-loss budget (`scripts/measure_contract_shadow.py`) from 3 to 1 — the one remaining case (`ambiguous_namespaced_leaf`) needs separate per-identity reachability work in `surface.py` and is unchanged.
