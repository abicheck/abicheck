### Fixed

- **A stored bundle's generation drift is now reported** — a `BundleFacts` package produced under different extractor/resolver semantics (ADR-062 D2) carries the same informational `coverage_warnings` notice a drifted `ProjectSnapshot` package already gets, on each per-library result of the run that loaded it. The verdict and exit code are unchanged.
- **Semantic changes to extraction and resolution now need a generation bump** — `storage/generation_fingerprints.json` records a content fingerprint of the extractor scope (`abicheck/extract/**` and the root parse-stage modules) and the resolver scope, each at the generation it was recorded at. A test fails when a scoped module changes without a re-record, naming the changed files; `scripts/record_generation_fingerprints.py --bump` or `--no-semantic-change --reason` is the one way to re-record. Edits outside those scopes do not affect it, and the fingerprint is the same for LF and CRLF checkouts, so a Windows autocrlf checkout does not report drift.
