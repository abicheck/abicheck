### Fixed

- **`type_reachability.directly_referenced_stdlib_type_spellings`'s typedef same-identity exception no longer accepts a structural namespace-suffix match that is itself a real, distinct captured identity elsewhere in the snapshot** (Codex review, fresh evidence). The structural-suffix branch added for the previous ABI-tag-coincidence fix correctly avoided the earlier `_stripped_signature_spelling`-based coincidence, but was itself unqualified: a typedef target can equal one of a stdlib identity's own bare namespace-suffix spellings while *also* being the real, distinct identity of an unrelated non-stdlib record/enum captured in the same snapshot — e.g. a DWARF `std::chrono::duration` alongside an unrelated global `duration` record, with a typedef `chrono::duration -> duration`. The target textually matches the stdlib identity's own bare suffix, but a genuinely different, captured `duration` record is exactly what it names, and the old check exported the stdlib identity's spellings anyway. Now a suffix match is rejected whenever the target is itself a captured non-stdlib identity; only an exact target match against the stdlib identity is still accepted unconditionally.
