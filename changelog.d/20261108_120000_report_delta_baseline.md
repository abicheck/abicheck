### Added

- **The JSON report now says whether it is the gate or the delta comparison of a `delta-baseline` run.** With `delta-baseline: main` the root Action compares the new side against the release baseline (the gate, which alone sets the verdict and exit code) and against the default-branch snapshot (the delta, shown in the PR comment). Both reports now carry an optional top-level `delta_baseline` block (compare report schema 7.3, release report schema 3.1): `comparison_role` (`gate` or `delta`), `decides_exit_code`, the base-snapshot `outcome` (or `unsupported_operand`), `base_sha`, `branch` and, on the delta report, the gate's `gate_verdict` and how the snapshot's library was paired with the PR's (`operand_match`). Before, only the PR comment said this, so a stored delta report read like an ordinary comparison. The Action passes the record with the new config key `report.delta_baseline` (`--set report.delta_baseline=@FILE`), marked `asserted_by: "action"`; the CLI checks its shape and the two roles' rules (exit 64 if unusable) and never lets it change a verdict, severity or exit code. `--no-baseline` and stored-BundleFacts comparisons refuse the key. The fork-PR publisher renders the delta notes from the block when a report has no delta analysis context.
