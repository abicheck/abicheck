### Fixed

- **Darwin C-linkage declarations keep their linker identity in the source ABI extractor** — on macOS, clang reports a plain-C or `extern "C"` declaration's `mangledName` with the Mach-O leading underscore (`_cfun` for `cfun`). The L4 clang extractor only recognized C linkage when `mangledName` equalled the bare name, so it dropped the `linker` key and reported the decorated spelling as a mangled name. Both the L4 extractor and the header-AST backend now apply one shared rule (`model.name_decoration.macho_underscore.is_c_linkage_mangling`, with `is_darwin_target` and `strip_darwin_itanium_decoration` moved there from `extract.headers.clang.context`). A C-linkage declaration's linker identity is the decoration-free name on every platform, matching the L2 header graph. A C++ `__Z...` name on Darwin is stripped to `_Z...` by the same rule, and an explicit `asm` label is never stripped. The extractor takes the target triple and language from the compile unit, falling back to the host default on a Darwin host so an unspecified `--target` keeps working.
