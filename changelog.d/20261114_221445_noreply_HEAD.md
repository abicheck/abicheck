### Fixed

- **Mach-O vtable and thunk layout checks** — the binary-only layout detectors
  (`VTABLE_SLOT_COUNT_CHANGED`, `VTABLE_THUNK_OFFSET_CHANGED`,
  `VTABLE_THUNK_SET_CHANGED`, `RTTI_INHERITANCE_CHANGED`) now read macOS dylibs
  as well as ELF. A Mach-O `nlist` has no size, so a `_ZTV`/`_ZTI`/`_ZTT`
  span is taken to the next label in its own section (`MachoExport.size`, with
  `size_bound_by` naming that label). A span is compared only when both sides
  name the same closing label, and a snapshot whose derivation did not run is
  reported as not evaluated. A pair with one ELF side and one Mach-O side is
  not compared by these detectors.

  A span is trusted only when the image's rebase and bind fixups inside it
  corroborate it: one relocated pointer word per slot (all but offset-to-top
  for `_ZTV`; every word for `_ZTI` and `_ZTT`). Unlabelled data between an
  object and its closer therefore cannot change a reported size. Images with
  chained fixups (`LC_DYLD_CHAINED_FIXUPS`) are not decoded yet, so they report
  no Mach-O object sizes; that is a known gap (WS-4 follow-up).
