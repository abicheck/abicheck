### Fixed

- **`--required-symbol @FILE` read failures are usage errors** -- a `@FILE` that exists but cannot be read (permissions, I/O error) used to escape `compare` as a raw traceback. It now exits 64 with `cannot read file (<reason>)`, the same way a missing file already did. A directory given as `@FILE` now reports "is a directory" instead of "no such file".
