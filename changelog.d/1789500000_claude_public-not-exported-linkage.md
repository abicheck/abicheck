### Fixed

- **`public_not_exported` no longer demands exports for inline, internal-namespace, or redeclared members, and no longer misses static members.** A member declared in its class and defined `inline` out of line (`inline void primitive::execute(...) const {...}`, the oneDNN `dnnl.hpp` shape) is inline under [dcl.inline]/6. The clang backend now folds inline-ness across every redeclaration of one mangled symbol. The castxml backend, whose XML only reflects the first declaration, now recovers it from the qualified out-of-line `inline`/`constexpr` declarations in the headers next to the member's own file. The obligation check also folds redeclarations itself, so stored snapshots benefit too. Declarations whose enclosing scope is an internal namespace (`detail`/`impl`/`internal`/anonymous) now owe no export, using the same convention `exported_not_public` already classifies with; this removes oneCCL's `detail::environment` noise. A `static` **member** function now keeps its export obligation. Previously every `static` declaration was skipped, so an unexported static member such as oneCCL's `communicator` factories was never reported. Only a namespace-scope `static` (internal linkage) is exempt now, told apart by Itanium's `L` marker or MSVC's static-member access code. The release-level reconciliation shares the same predicate.
- **`func_added`/`var_added` no longer read as an added export for a header-only declaration.** When the NEW side's export table confirms a newly declared function or variable is not exported (a pure virtual, an inline or `constexpr` function, or a `constexpr` constant), the finding's description now says "header-only (no exported symbol)". The kind and verdict stay the same, and each addition now carries `surface_facts` like removals already did.
