### Performance

- **`dumper_elf_symbols._pyelftools_exported_symbols` now resolves symbol names through the bounded string-table buffer.** The buffer added for `elf_metadata`'s dynamic-symbol walk was never wired to this second path, which builds its own `ELFFile` and walks both `.dynsym` and `.symtab`, resolving every `Symbol.name` with one seek-and-read per name. Each section is now buffered through its *own* associated string table (`.dynstr` for `.dynsym`, `.strtab` for `.symtab`, taken from the section so the pairing follows `sh_link`), using the same helper — no second string-table reader, and the same fall-through to pyelftools for an oversized, malformed or truncated table. Measured on a 30,000-symbol, 6.3 MB ELF shared object: 1.492s to 1.280s (**1.17x**) for the full two-table walk, with byte-identical results. As with the first buffering change, the modest end-to-end figure is the honest one — construct-based decoding of the symbol *entries* still dominates and is untouched here.

### Fixed

- **An acquisition identity no longer normalizes away the include search order.** `workflows.release_public_surface.build_side_identity` sorted the `includes` sequence before folding it into `SurfaceAcquisitionIdentity`, but that sequence becomes the compiler's `-I` search path, where order decides which of two same-named headers wins: with `a/choice.h` declaring `int api(void)` and `b/choice.h` declaring `long api(void)`, `-I a -I b` and `-I b -I a` produce different ASTs. Both orders keyed identically, so one side's acquired public surface could be reused for a request the parse would have answered differently. The order (and any repeated path, which shifts every later entry's precedence) is now preserved. The membership-only inputs — header files and roots, public header dirs — are still sorted, since those name a set rather than a search order.

- **`SpellingMatch` is now genuinely immutable, not merely documented as such.** `__slots__` bounds which attributes exist but does not make them read-only, so assigning to a cached match's `_text` changed the value returned to every subsequent reader of that cache key — the sharing invariant `compare.spelling_match_cache`'s own docstring advertises. Assignment and deletion now raise `AttributeError`.

- **The match cache's retained-bytes budget now counts the compiled patterns it keeps alive.** A match entry holds a strong reference to its pattern through `_keepalive`, and that reference outlives the vocabulary-cache entry that compiled it — the vocabulary cache is bounded at 64 entries and evicts independently — so an evicted vocabulary's pattern stayed retained while `retained_bytes` reported only the entry bookkeeping around it. A pattern's estimated cost now joins the budget when the first entry starts retaining it and leaves when the last one releases it, so eviction is driven by what is actually held. A pattern whose own cost exceeds the whole budget is bypassed rather than admitted, since admitting it would evict every other entry on the next insert and then be evicted itself.
