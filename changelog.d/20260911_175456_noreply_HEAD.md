### Fixed

- **`check-target`'s assurance-overlay/`run.sh` compile-context sources-root
  promotion no longer falls back to the checkout-root document when
  `--sources` names a tree with no `.abicheck.yml` of its own.** Enabling
  `analysis-assurance-complete` (or any input that triggers `action/run.sh`'s
  compile-context overlay) without an explicit `build-config`, while
  `--sources`/`inputs.sources` pointed at a directory with no config of its
  own, previously left the checkout's own `build:`/`sources:`/`compile:`/
  `source:`/`debug:` blocks (whichever are sources-root-exclusive for that
  run's mode) in the generated overlay — forwarding settings the real,
  non-overlay pipeline's own `discover_build_config(sources)` -> `None` ->
  `BuildConfig()` defaults resolution would never have applied. Both call
  sites now clear those blocks via the shared
  `abicheck.action_config_overlay.apply_sources_root_config_blocks`, matching
  the same clearing already applied for an existing-but-empty sources-root
  document.

### Security

- **`check-target`'s "Generate assurance-overlay config" step now escapes
  every untrusted path/exception it interpolates into a GitHub Actions
  `::error::` workflow command.** A direct `check-target` caller controlling
  `build-config`/`sources` (or a malformed `.abicheck.yml`'s own parser
  error text) could previously embed a literal newline that let the
  remainder of the value start a second, attacker-authored workflow command
  (e.g. a smuggled `::add-mask::`). Fixed by adding a `_gha_escape` helper to
  this step's own Python heredoc, mirroring `action/run.sh`'s existing
  identical helper, and applying it at every interpolation site.
