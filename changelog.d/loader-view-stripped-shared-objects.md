### Fixed

- **A stripped shared object dumps to the same exports as the intact one** — a `.so` whose section header table is zeroed, absent or removed by `sstrip` was refused with "no readable .dynsym section", although the dynamic loader finds every export through `PT_DYNAMIC`. `dump` and `compare` now read the dynamic symbol table the way `ld.so` does (`DT_SYMTAB`, `DT_STRTAB`, `DT_STRSZ`, `DT_SYMENT`, the `DT_GNU_HASH` or `DT_HASH` count, and `DT_VERSYM`/`DT_VERDEF`/`DT_VERNEED`) when a section is missing, and the stripped object yields the same names, versions, bindings, visibility and code hashes as the intact build. A dynamic table that is itself corrupt, truncated or absent is still refused with exit 1. The read lives in `abicheck.extract.elf_loader_view`, and the symbol-origin heuristics moved from `abicheck.elf_metadata` to `abicheck.extract.elf_symbol_origin`.
