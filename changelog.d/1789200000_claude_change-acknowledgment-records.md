### Added

- **Change acknowledgment records (ADR-067 D5/D6).** A loaded `AcknowledgmentList` (`checker.compare(acknowledgments=...)`) can now record that a specific, already-detected finding was intentionally accepted — bounded to an exact `finding_id`/`symbol`, a component, and a release range, never a broad pattern (a broad selector is rejected at load time, and an ambiguous match across records is a hard error rather than a silent nearest-match). An acknowledged finding keeps its verdict class and gate contribution; only a new `acknowledged_by` overlay is added to its disposition record, mirroring how `reclassify:` already works. A policy file's new `acknowledgment: unacknowledged_additions: allow|warn|block` block (default `allow`, so no existing run changes) additionally reports — and, under `block`, gates on — a public addition with no acknowledgment, as an orthogonal exit axis that never reclassifies the addition itself. See [Change acknowledgment](https://github.com/abicheck/abicheck/blob/main/docs/use/acknowledgments.md).
