### Fixed

- **The composite Action no longer misses, mis-detects, or mis-renders a report when `extra-args` overrides `format:` in either direction.** ADR-064's "effective-format-override" gap: a `format: text`/`markdown` step whose own `extra-args` supplies `--format json` (or the reverse) really does change what `abicheck` outputs — Click keeps only the last repeated `--format` occurrence — but nine of `action/run.sh`'s format-dependent decisions all gated on the Action's own nominal `format:` input instead of the effective value: three report-*discovery* sites (the stdout-JSON capture, its `OUTPUT_FILE` JSON branch, and the text-report reader `_severity_gate_exit`/`_severity_gate_categories` both read through) silently missed the override and left annotations/coverage/severity/verdict queries with no report to read; two report-*production* decisions (compare and scan mode's own `--write json=...` sidecar injection) skipped writing a secondary JSON report because the nominal format looked already-JSON; two step-summary *rendering* decisions (the "Format" row, and the markdown-vs-code-fence choice for the embedded report) mislabeled or mis-fenced the real output; `format: sarif` overridden away from sarif still defaulted `output-file` to the sarif-shaped filename a workflow's own `upload-sarif` step looks for, ready to silently feed non-SARIF content to CodeQL; and the annotation renderer's own "no JSON report available" diagnostic could be suppressed by the very override it exists to explain. Fixed by a new `_effective_format` helper (mirroring `_extra_args_has_write_flag`'s own `extra-args`-scanning pattern) that all nine sites now consult instead. Separately, the `format: sarif` + `upload-sarif: true` combination is now safe even with an *explicit* `output-file:` (not just the default path): the `report-path` output — the exact value `upload-sarif`'s own gate condition requires — is withheld whenever the effective format isn't sarif, so a mismatched run is skipped rather than uploaded.
