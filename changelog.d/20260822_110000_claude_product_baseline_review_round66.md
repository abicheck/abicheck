### Fixed

- **`TarExtractor` now revalidates a hard link's target when it names a symlink, rejecting a relocated escape.** A symlink `a/b/link -> ../../safe` validates safely at its own nested location, but `tarfile.TarFile.makelink()` falls back to a full copy whenever `os.link()` fails -- and for a hard link naming that symlink (e.g. `x -> a/b/link` at the archive root), the fallback re-extracts the *original* symlink's own unmodified, relative target text at the hard link's own, differently-nested location, which the same text can escape the extraction root from even though the original symlink never could. Since whether `os.link()` actually fails is filesystem-dependent and unknowable at validation time, this is now treated as a worst case: a hard-link member naming a (possibly transitively-aliased) symlink has that symlink's target text revalidated as if it were being recreated at the hard link's own path, before extraction is allowed to proceed.
