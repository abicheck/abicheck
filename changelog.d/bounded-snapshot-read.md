### Fixed

- **Snapshot reads no longer allocate the safety cap.** `snapshot_io.read_snapshot_bytes` read a whole file with `f.read(cap + 1 - len(prefix))`, where `cap` is the gigabyte-scale decoded/stored safety ceiling — so reading an 8 KiB snapshot requested ~1 GiB from the buffered reader. Linux's overcommitting allocator hid the cost entirely; Windows commits and zeroes, which made the stored-package comparison paths dominate the Windows CI wall clock (one stored-versus-live parity test measured 118.03s before and 1.80s after, assertions unchanged). The read is now chunked, preserving the single file descriptor (so FIFOs and `/dev/stdin` still work), the total byte bound, and the one-byte overshoot that detects a file growing past its `fstat` size.

### Changed

- **Superseded `push` runs are now actually cancelled.** Six read-only validation workflows grouped concurrency by `${{ github.event.pull_request.number || github.run_id }}`. A `push` event carries no PR number and every push has a distinct `run_id`, so each landed in its own group and `cancel-in-progress: true` never cancelled an obsolete `main` run — the newer commit's run queued behind it. They now group by ref on `push` while keeping `run_id` isolation for `schedule`/`workflow_dispatch`. `tests/test_workflow_concurrency_grouping.py` evaluates every cancelling workflow's real group expression against synthesized event contexts, so a future workflow copying the old spelling fails there.

- **CI: path filters now cover their own build infrastructure.** `examples-validation.yml`, `realworld-validation.yml` and `clang-plugin.yml` filtered on the inputs they validate but not on `pyproject.toml`, `action/**`, or the scripts their composite actions execute — so re-pinning CastXML in `action/install-castxml.sh`, or changing a dependency bound, could merge without any job that depends on it having run. `ci.yml`'s `heavy-parity-gate` already named that set for exactly this reason; the other three now do too, with `tests/test_workflow_path_filter_closure.py` deriving each workflow's dependencies from what it actually executes.
- **CI: dropped coverage instrumentation that nothing read.** The macOS unit lane wrote a `coverage.xml` the Codecov upload (gated to Linux/3.13) never took, and the `slow` lane wrote a `coverage-slow.xml` referenced nowhere in the repository. Both are gone and every test still runs; instrumentation costs ~60% wall time. The `COVERAGE_CORE=sysmon` request is documented as inert (sys.monitoring cannot measure branches before Python 3.14, so coverage.py falls back to CTracer) rather than left claiming otherwise, and `tests/test_coverage_core_effectiveness.py` fails if that stops being stated.

### Security

- **Workflows may no longer interpolate attacker-controlled free text into a `run:` body.** A PR title, body, branch name or comment body is substituted by `${{ }}` *before* the shell parses the script, so it must arrive through `env:` instead. Both places this repository reads such text already did that correctly, but nothing enforced it. `tests/test_workflow_untrusted_text_interpolation.py` adds a repo-wide structural scan plus a real execution of the real step against hostile payloads, and a control proving the harness can detect an injection at all — the #705→#758 lesson that asserting YAML text is not evidence.
