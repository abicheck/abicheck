### Changed

- **A typed compare side can state what the CLI's inline `dump` does** — `CompareRequest.resolved_collect_mode` (a front end's own collect mode, e.g. from `.abicheck.yml` `source.method` or `--since`, winning over depth/input inference as `DumpRequest.resolved_collect_mode` does) and `InputSpec.execution` (the side's `DumpExecutionOptions`: config and its trust, the `-p` compile-database match, the L2 seed's collect mode, the folded L4 compiler, the changed-path seed) let `resolve_compare_request` collect a raw `--sources`/`--build-info` side the way the native `compare` CLI's nested `dump` does; the pre-flight planner checks only an explicit (`build_config_explicit`) config. The `-p` match now has one owner (`workflows.artifact.compile_db_match.match_side_compile_db`) for `dump` and `compare`.
- **Raw evidence a run cannot collect from is ignored with a note on every route** — a raw source tree or build directory on a side whose operand is a stored JSON snapshot or `Module.symvers` manifest, or at a depth that collects no build/source evidence (`binary`/`headers`), is now dropped with a warning by `run_compare_request` too, as the CLI already did; prebuilt packs are kept. Before, a typed request embedded live evidence into the stored snapshot, folded the build directory into a `headers`-depth parse, and rejected a `hybrid`/`android` frontend for a tree it then could not use.
