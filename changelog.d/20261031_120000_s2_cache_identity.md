### Fixed

- **The dump and header-AST caches key on content, not mtime (ADR-062 D11)** —
  touching an unchanged header no longer discards a warm snapshot, and the
  keys now see every file a parse can read: any file under an include root
  whatever its suffix (`.def`, `.in`, suffix-less `<vector>`), a file passed
  as an include, the compiler's built-in system include directories, and the
  directories `CPATH`/`C_INCLUDE_PATH`/`CPLUS_INCLUDE_PATH` add. Before, an
  edit to any of those could reuse a stale cached snapshot or AST. Every
  header-bearing cache entry is re-keyed once.
- **Dependency scoping of a cache-reloaded snapshot matches a fresh dump** —
  the cache now keeps the declaring-header attribution of constants and
  typedefs beside each entry, so scoping a reloaded snapshot drops the same
  system typedefs a fresh extraction drops (libssl: 821 kept before, 652
  now, as fresh).
