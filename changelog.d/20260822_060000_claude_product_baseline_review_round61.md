### Fixed

- **`TarExtractor`'s declared-content-size guard (`_reject_oversized_declared_content`) now also caps tar member *count*, independent of the existing declared-byte-sum limit.** Millions of duplicate zero-length members leave the byte sum at zero -- never tripping the existing check -- while `tarfile.TarFile.getmembers()` still eagerly materializes and retains a `TarInfo` object for every one of them, letting a highly compressible archive exhaust memory before anything is rejected. The guard now iterates the archive directly (`for member in tf:`) instead of calling `getmembers()` first, and rejects as soon as either the declared-byte-sum limit or a new, independent member-count limit (`DEFAULT_MAX_TAR_MEMBERS`, 200,000, overridable via `_ABICHECK_TAR_ZST_MAX_MEMBERS`) is exceeded -- stopping the loop before the rest of a malicious archive's headers are ever parsed.
- **`pack_product_baseline()` now preserves the executable bit for a source file executable only for its group or others (e.g. mode `0o055`), not just the owner.** The deterministic mode-normalization step previously checked only the owner-execute bit (`0o100`); a file with no owner-execute bit but a group- or other-execute bit was silently normalized to `0o644` on pack, dropping every executable permission on unpack. Now checks all three permission classes (`0o111`).
