### Added

- **`abicheck/model/fact_registry.py`, a declarative fact/capability
  registry** (ADR-063 D7/Phase 5), generalizing `change_registry.py`'s
  single-declaration `ChangeKindMeta` pattern from change *kinds* to
  *facts*. Every `Fact[T]`-typed model field now has exactly one
  `FactDefinition` entry declaring its value type, producing backends, and
  whether it participates in persistence/identity/comparison/suppression/
  reporting -- closing the "add a field, touch nine files" cost the
  ELF-binding incident (PR #734) is the canonical example of. A new
  `fact-registry-completeness` AI-readiness check
  (`scripts/fact_registry_completeness.py`) enforces this both ways: every
  converted field has a registry entry and vice versa, and a real
  repo-wide scan finds every field that is availability-ambiguous
  (flag-backed, or a documented tri-state annotation) but not yet
  converted, requiring it to be named in an allowlist-and-shrink baseline
  (`fact_registry.KNOWN_UNCONVERTED_ELIGIBLE_FACTS`) rather than silently
  passing. `docs/reference/fact-registry.md` (new, generated by
  `scripts/gen_fact_capability_matrix.py`) publishes the registry.
- **`RecordType.is_final` now carries a `Fact[bool | None]` sibling**
  (`is_final_fact`, schema v30) -- this phase's own worked-example
  conversion, alongside the five fields Phase 0 already converted. Unlike
  those five, it needs no private omission sentinel or snapshot-level
  reliability flag: `is_final`'s own `None` already unambiguously means
  "not captured", so the legacy-to-`Fact[T]` bridge is a direct
  None-vs-real-value mapping. No detector reads the new sibling yet
  (unchanged from Phase 0's own scope), and no existing behavior changes.
