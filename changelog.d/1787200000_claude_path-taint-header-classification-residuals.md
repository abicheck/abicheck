### Fixed

- **CastXML no longer leaks a checkout-dependent path into a synthesized constructor/destructor identity.** `_qualified_name`'s namespace/class-scope walk copied a lambda-templated class's own raw `context` name verbatim, so two byte-identical header trees checked out under different paths could still synthesize two different ctor/dtor `Function.mangled` keys (`~demo::raii_guard<(lambda at /tmp/a/lib.hpp:4:37)>` vs. `~demo::raii_guard<(lambda at /tmp/b/lib.hpp:4:37)>`), fabricating a spurious `func_removed`/`func_added` pair.
- **A header-only public type named by no exported function/variable signature is no longer demoted as `non-public-type`.** `compute_public_surface` now also seeds its reachability closure from record/class types with a confirmed public-header origin (mirroring the existing enum precedent and `internal_leak.py`'s own broader seed, gated by the same internal-namespace exclusion), so a header-only/templates-only library's utility types (e.g. oneDPL's `discard_iterator`) are no longer silently excluded from the compared surface merely because nothing exported references them by name.
- **The default/root-cause markdown report now discloses when findings were filtered as non-public ABI surface.** Previously only `--show-filtered`, JSON, and SARIF output carried any trace of `out_of_surface_count`; the plain-text/markdown report gave no indication that real findings had been demoted, so a run could read `NO_CHANGE`/exit 0 with the filtering invisible.
