### Added

- **Unused policy rules are reported, and can fail a run** — the audit now enumerates every configured suppression, `reclassify:` and acknowledgment rule, including one that matched nothing, and gives each one a `status` (`active`, `shadowed_only`, `not_evaluated`, `unused` or `expired`). A new top-level policy key `unused_rules: allow|warn|block` (default `allow`) makes `block` add a `0`/`1` floor to the exit code, folded with `max`, so it never lowers a real failure. `compare --fail-on-unused-rules` does the same for one invocation and can only tighten. Only status `unused` triggers the gate, and a rule whose detector did not run reads `not_evaluated`, never `unused` (ADR-067 P1; see `docs/reference/exit-codes.md`).
- **Optional `id:` on suppression and `reclassify:` entries** — a user-chosen identifier, unique within its file (a repeat is an error), reported as the audit's `rule_id`. `id:` never changes what a rule matches. Shadowed matches (`shadowed_count`) and, for reclassify, selector hits are reported next to the disposed-of count.
