### Fixed

- **A warm L2 AST cache hit now enters the same request-local acquisition as a compiler run** — clang and CastXML disk-cache decodes moved inside the per-request, per-key singleflight, so later release members, later worker groups and the header-graph pass reuse the one decoded root (and the producer's own resolved language mode, DPC++ context and CastXML `(compiler, force_cpp)` selection) instead of each decoding the cache file again. On a six-DSO directory compare this takes warm-cache raw AST decodes from 25 to 3 (CastXML) and 13 to 2 (clang), and neutral `SemanticIR` normalizations from 12 to 1, with identical findings. Streaming dependency-declaration pruning is disabled inside an acquisition scope for the same reason it already is inside the memo scope: the exact parsed root is handed to a consumer that walks it raw.
