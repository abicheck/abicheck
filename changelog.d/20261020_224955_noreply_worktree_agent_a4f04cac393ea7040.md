### Fixed

- **A template instance the new header stops instantiating is no longer reported as a removal while its template is still declared** — at header depth, castxml lists an instantiation only while some header uses it, so a template the new header merely stops using read as `func_removed` or `inline_function_removed` even though the declaration remains and the new binary may still export the symbol. Such an instance now reports `func_visibility_changed` (BREAKING) when the library stopped exporting it, and nothing when the library still exports it. An export loss keeps its binding and its BREAKING verdict. A `finding_id` suppression written against the old `func_removed` for such a symbol stops matching. Class-template specialization members the new header no longer instantiates (their implicit constructors, destructor and `operator=`, and the specialization's own `type_removed`) keep their existing kinds; see `docs/contribute/known-gaps.md`.
