### Fixed

- **A C++20 library's headers parse without build data** — `dump`/`compare` of
  an ELF library whose public headers use C++20 syntax (`concept`, `requires`)
  in an included sub-header failed castxml's default C++17 parse and aborted.
  The image's own DWARF producer (`DW_AT_producer`, falling back to
  `DW_AT_language`) records the dialect it was built with, so a C++20 or C++23
  build is now parsed as `-std=gnu++20`, and the `-m` target flags the producer
  records (e.g. `-mavx2`, which gates `__AVX2__` intrinsics) are forwarded.
  Both are visible in the snapshot's `ast_toolchain` provenance as
  `implied_options`, and `language_standard_explicit` stays `0` for an inferred
  standard. The standard is refined only in a parse that is already C++, so a
  C header in a C++ library stays C, and a flag the caller gave always wins.
  C++20/23 binaries are parsed in C++20 mode, since castxml has no C++23 mode.
  Stripped images with no DWARF producer are unchanged.
