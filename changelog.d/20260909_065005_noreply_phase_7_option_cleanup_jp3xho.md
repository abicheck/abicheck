### Removed

- **`compare --keep-extracted`/`--no-bundle-analysis`/`--max-json-object-nodes` are gone** (Phase 7d remainder + 7g, `docs/contribute/plans/one-comparison-product.md` §4.1). `--keep-extracted` and `--no-bundle-analysis` have no replacement — extraction cleanup on a directory/package `compare` is now unconditional, and bundle-level cross-library analysis always runs. `--max-json-object-nodes` is replaced by `.abicheck.yml`'s `resource_limits.max_bundle_facts_decode_nodes`; its default (`bundle_facts.DEFAULT_MAX_JSON_OBJECT_NODES`, unchanged at `1_000_000`) is now backed by a real measurement against a synthetic oneDAL-scale corpus rather than an unverified guess, kept deliberately conservative rather than raised, since a higher ambient default would widen every unconfigured/untrusted run's own decode-bomb ceiling — a project with a real large-blob need sets the new config key explicitly instead. The GitHub Action's `keep-extracted` input is removed too.

### Fixed

- **`resource_limits.max_bundle_facts_decode_nodes` can only be raised by an explicit `--config`, on the native CLI and the GitHub Action alike.** A stored-BundleFacts-OLD_INPUT `compare` previously read this key from `.abicheck.yml` the same way whether it was named on the command line or auto-discovered by walking up from the current directory — but that key raises the pre-`json.loads()` decode-bomb budget over content (the BundleFacts documents themselves) that may be attacker-controlled, so an auto-discovered config from the same untrusted checkout being decoded (e.g. a PR's own working tree in CI) could raise its own ceiling. An auto-discovered value can still *lower* the budget (never a decode-bomb risk) but no longer raises it past the default. The Action's own `--config` overlay synthesis (triggered by any release-topology/compile-context input) had the identical gap one level up — it merges the repository's auto-discovered `.abicheck.yml` into an always-explicit `--config` file, which would otherwise launder a raised value into trusted status; it now caps the merged value the same way.
