### Fixed

- **A directory or package `compare` pairs a stored snapshot with the live library it was dumped from** — a member the file name cannot pair is now paired by the library it records (`AbiSnapshot.library` for a stored snapshot, the file name for a live binary). A directory of `abicheck dump` outputs named `libfoo.json` against the live `libfoo.so.1` directory used to pair nothing and exit 1 (`no_comparison_completed`); it now compares every member, in either direction, whatever the dumps are called. This applies to directories, stored `ProjectSnapshot` packages and `BundleFacts` documents. Every pair the file names already made is kept, and a library claimed by two unpaired documents on one side pairs nothing. `compare OLD.bundle-facts.json NEW_PACKAGE_DIR` now reads a stored NEW package's own members instead of its object store (a NEW package recording degraded members is refused, exit 64).
- **A one-sided release member no reader can open is reported `failed`, not unmatched** — a file discovered by its `.so` name alone (`notes.so` holding text, an empty file, a JSON file that is no snapshot, a linker script naming nothing) with no counterpart on the other side used to read as a plain `not_supplied` member. It is now `failed` on the scope record with an `ERROR` library entry and `operational: extraction_error`, which is what the same file reads as once it pairs. This holds on the live/live and the stored-OLD/live-NEW routes, for OLD-only and NEW-only members. A linker script naming a real member stays readable. Only the file format is probed: a damaged ELF image without a counterpart is still a one-sided member.
