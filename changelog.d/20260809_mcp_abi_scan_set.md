### Added

- **New MCP tool `abi_scan_set`** — the multi-artifact sibling of `abi_scan`, mirroring `scan --artifact-set` (ADR-056/G35). Audits 2+ library files that together make up one logical product (e.g. `libcore.so` + `libalgo.so` behind one shared header tree) as a single unit: each member gets the same always-on tier + pinned evidence level a single-binary `abi_scan` runs, plus one cross-library bundle-audit pass over the whole set. Routed through the pre-existing `run_scan_set_subprocess` (its own docstring already anticipated this caller). Deliberately a separate tool rather than an `artifact_set` parameter grafted onto `abi_scan`: `run_scan_set` is audit-only by construction (ADR-056 D2, rejects a baseline outright), so `abi_scan`'s `against`/`policy`/`suppression_file`/`contract_evaluation` family has no equivalent here and isn't accepted — the same reasoning `cli_scan.py` already applies by giving `--artifact-set` its own CLI code path. `docs/reference/mcp-tools-reference.md` regenerated.
