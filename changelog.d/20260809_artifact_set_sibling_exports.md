### Fixed

- **`scan --artifact-set`'s `public_not_exported` cross-check no longer flags a declaration a *sibling* member of the same set exports** (G35, previously an acknowledged limitation — see AGENTS.md's "multi-artifact scan" entry). A shared umbrella header commonly declares more than one member's own public API (e.g. an `oneDAL`-shaped product where `libcore.so` and `libalgo.so` both `#include` one header): scanning each member's own snapshot in isolation had no way to see that a symbol it doesn't itself export is satisfied elsewhere in the same product, so a correctly-split multi-DSO product false-positived as an `API_BREAK` under `--crosscheck public_not_exported=error`. `bundle.artifact_set_member_exports()` now runs a cheap, ELF-header/dynsym-only pass over every set member up front, and `service_scan.run_scan_set()` hands each member's own scan the union of what its *siblings* export via a new `CrosscheckConfig.sibling_exported_symbols` field, consulted by `buildsource/crosscheck.py`'s `_check_public_not_exported` alongside this member's own export table and the existing L4 reconciliation set. `run_scan_set()` also rechecks `--budget` right after this new pass, since it has no internal checkpoint after its last member's parse. Minimum viable fix (not full per-declaration ownership attribution, and no cross-member L4 reconciliation of variant export spellings — both flagged as known gaps rather than fixed here; per G35's own tracked scope): "some sibling exports it" clears the finding regardless of which member the header intended to own it. Single-binary `scan`/`compare` are unaffected — the new field is empty everywhere outside `run_scan_set`.
