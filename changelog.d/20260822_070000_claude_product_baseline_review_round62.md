### Fixed

- **`pack_product_baseline()` now refuses to publish an archive that `unpack_product_baseline()` would always reject**, instead of silently producing one. The tar member-count and declared-content-byte limits `TarExtractor` enforces on read (see the previous round's changelog entry), and the manifest-size limit `unpack_product_baseline()` enforces separately, now have matching pack-time checks: a product with too many packed paths, too much file content, or a manifest that serializes too large now fails fast with a clear `SnapshotError` naming the same overridable environment variable the reader honors, rather than writing an archive that can never be unpacked.
- **`pack_product_baseline()` no longer leaks the temporary file descriptor when `os.chmod()` fails** after `mkstemp()` succeeds (e.g. on a filesystem that permits creation but rejects mode changes). The descriptor hadn't yet been handed to `os.fdopen()` at that point, so ownership was still the caller's to close; repeated failed packing attempts could previously exhaust the process's file descriptors.
- **`strip_vendor_hash()` now matches an auditwheel/delocate content-hash suffix case-insensitively.** A vendored library carrying an uppercase-hex or uppercase-extension hash (e.g. `libfoo-ABCDEF123456.so.1`) previously wasn't recognized as hash-suffixed at all, so two releases differing only in that generated hash's case keyed as unrelated libraries and were reported as spurious removal/addition noise on every rebuild instead of being treated as unchanged.
