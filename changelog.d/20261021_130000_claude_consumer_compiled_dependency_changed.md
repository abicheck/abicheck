### Added

- **`PUBLIC_CONSUMER_COMPILED_DEPENDENCY_CHANGED` flags a changed dependency of a public inline or template body** — when a public inline or template function's body, written in a public header, starts or stops calling or referencing another declaration between two versions, `compare` now reports a `COMPATIBLE_WITH_RISK` header-graph finding. Every consumer that includes the header compiles that body into its own code, so it must recompile to pick up the new dependency. The finding names the added and removed dependencies. It is never a break on this evidence: no consumer build data says which consumers include the header, so the finding never claims a consumer is affected and never reads an unused dependency as absent. A narrowed, degraded or missing header call pass on either side produces no finding and no clean claim. Implemented in `compare/consumer_compiled_dependency.py` and wired beside `virtual_dispatch_set_findings` in `buildsource/evidence_report.py`. Covered by `catalog/cases/case222` (changed inline-body dependency set) and `tests/test_consumer_compiled_dependency_findings.py` (positive, reordered, private-header, out-of-line and incomplete-evidence shapes). The consumer-build tier that could prove a break is not implemented.
