### Fixed

- **A widened enum underlying type is a break without debug info** — `ENUM_UNDERLYING_SIZE_CHANGED` came only from the DWARF layout pass, so a headers-plus-binary compare of `enum E : unsigned char` → `enum E : unsigned int` on a by-value parameter read NO_CHANGE (exit 0). The header model's own underlying type is now compared by byte size (`compare/enum_underlying.py`); `long` takes its width from the side's data model (LLP64 on PE, the ELF pointer size otherwise), and an unknown spelling never reports. With debug info the two tiers' findings collapse into one.
- **`result_counts` partitions the retained findings** — a redundant finding the legacy verdict still scores made the summary read "4 retained (5 gating, 0 non-gating)", and `non_gating` was clamped from `retained - gating`. The new `result_counts.gating_retained` is the retained findings that gate, `non_gating` is `retained - gating_retained`, and the line names the folded finding: "4 retained (4 gating, 0 non-gating) + 1 gating folded into another finding (still scored by the verdict)". `gating` keeps the ledger's total.
