### Fixed

- **Warm `compare` runs hit the whole-snapshot cache again** — `compare` always threads a `CompileContext` (even an all-default one), and the cache used to refuse any non-`None` context, so every warm run re-parsed the headers. The cache key now folds in the context's normalized content (`service_dump_cache.compile_context_cache_field`, with an explicit `--ast-frontend` resolved through `effective_header_backend` and compiler/clang identities resolved with the context's `gcc_path`/`gcc_prefix`); a `None` and an all-default context share one key.
- **No false "not comparable" when an `--exclude-header` pattern matches only one release** — snapshots record the exclusion patterns that actually removed a header, so `--exclude-header "*_ze*"` against an old release without `dnnl_ze.h` recorded the pattern on NEW alone and the pair was refused (exit 16) after both sides had been parsed. A pattern recorded on one side only is now accepted when the other side's parsed surface contains no declaration from a header it matches (`model.header_exclusion_record.exclusion_asymmetry_is_vacuous`); a side that really parsed such a header, or carries no header evidence at all, is still refused. The coverage warning applies the same rule.
- **`compare --dry-run` predicts the header frontend the run will use** — it resolves the frontend with the same functions the dump calls and blocks (exit 1) when that frontend's tool is missing, instead of listing clang as found and estimating a runtime for a run that then failed with "castxml not found in PATH". The check runs only when an operand the real run extracts live parses headers (`workflows.header_frontend_preflight.operand_parses_headers`): two stored snapshots never block on `-H`, and a `--dump-manifest` side is checked even without `-H`. Under an explicit `--compiler`/`--compiler-prefix`, castxml's emulated compiler (resolved by the dump's own `_resolve_compiler_binary`) must also be on PATH.
- **One unparseable header no longer sinks a whole `-H` directory under castxml** — when a multi-header parse fails, each compile error is attributed through its include chain to the top-level header that produced it; those headers are dropped with a warning and the parse retried (`extract.unparseable_header_fallback`). The dropped headers are recorded on the snapshot (`ast_toolchain["unparseable_headers_excluded"]`) and reported as reduced evidence, with an extra warning when only one side dropped a header. Unattributable errors, toolchain-version failures, and a single `-H` file still fail as before.
- **`--lang c` over a C++ header set no longer lets one unparseable header abort the whole parse** — when the C-mode castxml run fails, the C++ retry also fails, and the failure is ordinary header diagnostics (not a frontend-version signature), the re-raised C-mode error is now marked as a failed language-mode retry (`SnapshotError.language_retry_failed`) carrying the retry's diagnostics (`attribution_stderr`), and the unparseable-header fallback attributes and excludes the failing header from those. Frontend-version mismatches and an unsupported castxml still fail as toolchain errors (`dumper_castxml_probe.castxml_failure_is_header_specific`).
- **Unparseable-header attribution drops the listed input, not a listed header it includes** — when listed header A includes listed header B and B fails only under a macro A set, the aggregate TU's own include frame (which names A) now takes precedence over the inner listed path, so only A is excluded and B keeps its declarations. An inner located header is used only when no aggregate frame identifies the input.
- **A warm cache hit no longer serves a snapshot parsed from stale sysroot/`-I`/`-include` headers** — keying a `CompileContext` recorded only the spelling of `--sysroot` and compiler options, not the header content they point at. The sysroot and every `-I`/`-isystem`/`-iquote`/`-idirafter`/`--sysroot`/`-isysroot`/`-include`/`-imacros` operand (separate, joined, or `=` form) are now content-hashed with the same include-tree walk `-I` directories get (`extract.compile_header_inputs`); a context naming an input that walk cannot follow (response file, `-iprefix`, PCH, VFS overlay, module map) is not cached.
