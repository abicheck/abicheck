### Added

- **The JSON report now says which baseline the root Action compared against.** The compare report (schema 6.8) and the directory/package release report (release schema 2.8) carry an optional top-level `baseline_provenance` block: `source` (`legacy-asset`, `baseline-set` or `direct-path`), `asset_name`, `project_ref`, `generation` and `profile`, the same values as the Action's `baseline-*` outputs. The Action passes them with the new config key `report.baseline_provenance` (`--set report.baseline_provenance=@FILE`, a JSON file). The block reads `asserted_by: "action"` because the CLI checks only the file's shape, not its values; a missing or malformed file is a usage error (exit 64) before any analysis. `--no-baseline` and stored-BundleFacts comparisons refuse the key. The schema reserves `members` for later per-member provenance. A `--set PATH=VALUE` whose value starts with `@` is now taken as written (YAML could not parse it before).
