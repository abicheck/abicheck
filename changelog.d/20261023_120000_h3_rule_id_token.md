### Changed

- **Breaking for report consumers: the `rule_id` of a suppression or `reclassify:` rule without an `id:` is now a portable token, `rule-<12 hex>`.** It used to be the rule's identity string with Python `repr()` spellings inside it, such as `to='risk'|symbol_pattern='.*'|expires=datetime.date(2027, 4, 1)`, which could not be pasted into an acknowledgment file and depended on the Python version. The new id is the first 12 hex digits of the SHA-256 of the rule's canonical identity (sorted-key JSON of its selector and gate fields, dates in ISO 8601, enums by value). It matches `[A-Za-z0-9._-]+` and does not change with YAML key order. A rule's own `id:` is still used unchanged. The readable identity in the effective-configuration receipt (`suppressions.rules`) is now that canonical JSON instead of the `repr()` form, so suppression-config digests computed from it change once. ADR-067 D3 is amended.
