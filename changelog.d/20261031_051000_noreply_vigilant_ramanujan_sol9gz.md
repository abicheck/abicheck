### Performance

- **Stored snapshots load their declarations, types and debug layout on first use** — for a snapshot written by a current abicheck (recorded header provenance, current schema, no closure markers), `load_snapshot` now leaves the `declarations`, `types` and debug-layout sections undecoded until something reads `snapshot.declarations` or `snapshot.semantic_ir` (ADR-062 D18). Loading a 140 MiB snapshot took 2.4-2.8 s instead of 3.9 s; the first read then costs what the eager load did, so load plus first access takes the same time and peak memory as before. The `abicheck` CLI still decodes every section at load (its comparisons read them all, and a malformed section stays a load error); a multi-library project `compare` measured 29.7-30.2 s before and 31.5-35.9 s after in one 8-library synthetic test. Saved bytes, digests and compare results are identical. Other documents decode eagerly. Through the Python API, a malformed declarations section in a current-format snapshot is reported when it is first read, not at load, as the header graph already was.
