### Performance

- **Stored snapshots load their declarations, types and debug layout on first use** — for a snapshot written by a current abicheck (recorded header provenance, current schema, no closure markers), `load_snapshot` now leaves the `declarations`, `types` and debug-layout sections undecoded until something reads `snapshot.declarations` or `snapshot.semantic_ir` (ADR-062 D18). Loading a 140 MiB snapshot took 2.4-2.8 s instead of 3.9 s; the first read then costs what the eager load did, so a full `compare` takes the same time and peak memory as before. Saved bytes, digests and compare results are identical. Other documents decode eagerly. One visible difference: a malformed declarations section in a current-format snapshot is reported when it is first read, not at load, as the header graph already was.
