### Changed

- **Audit rule rows cover every configured rule (report schema 6.3)** — `disposition_audit.rules`, `reclassifications` and `acknowledgments` now carry one row per configured rule, including zero-count rules, where they previously listed only rules that disposed of a finding. Consumers that assumed a non-empty list must accept zero-count rows. Each row gains `status`, `shadowed_count`, `selector_matched_count` and `entry_index`; reclassify rows add `changed_count` (equal to `matched_count`, which keeps its meaning).
- **`rule_id` of a `reclassify:` rule is its `id:` or canonical identity** — previously the rule's `label` or `reason` (or its target verdict), so distinct rules that shared a label collapsed into one row. `label` and `reason` are reported as their own fields. A suppression rule's `rule_id` is unchanged unless it sets `id:`. The per-finding `reclassified_by` value is unchanged.
- **`suppression_audit.stale_rules` is a projection of the disposition inventory** — it lists the rule ids that matched nothing or were only shadowed by an earlier rule (previously the labels of rules with no overlapping match), and it no longer lists a rule whose detector did not run. A run whose exit code depends on `stale_rules` should re-check it.
- **Duplicate `id:` values are rejected** — a policy or suppression file that repeats an `id:` now fails to load with a `PolicyError` (exit `64`).
