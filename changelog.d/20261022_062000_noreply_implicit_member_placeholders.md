### Fixed

- **Implicit special members of a new or removed struct no longer appear as added/removed symbols under internal `__abicheck_ctor__…` names (#1713).** castxml declares an implicit default/copy/move constructor, copy/move `operator=` and destructor for every record — including plain C structs parsed as C++ — and abicheck keys the constructors and destructor on internal placeholders. When the owning record was itself new (or gone), each of those members was reported as `func_added` (or `inline_function_removed`), so a release adding a few C structs listed dozens of `__abicheck_ctor___foo_t()`-style "symbols" in JSON, Markdown and SARIF. They are now treated as part of the record's own `type_added`/`type_removed` (`abicheck/compare/implicit_member_surface.py`), and unexported implicit members are no longer listed in a type change's `affected_symbols`. An implicit member that appears or disappears on a struct present in both versions (e.g. a `const` member deleting the implicit default constructor) and any implicit member an export table confirms are still reported.
