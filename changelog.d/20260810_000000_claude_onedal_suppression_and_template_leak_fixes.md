### Fixed

- **`namespace`/`entity_namespace`/`cause_namespace` suppression globs now give ``**`` real globstar semantics** — a straight `fnmatch.translate` compiled `**` as an ordinary `.*` glued to whatever literal text followed it, so two starred regions were still separated by a *mandatory* literal `::`: a rule like `oneapi::dal::**::detail::**` could never match the zero-segment case `oneapi::dal::detail::...`, only a case with at least one intervening namespace segment (`oneapi::dal::backend::detail::...`). `**` now matches zero or more complete `::`-separated segments, absorbing its own adjoining `::` separator, so `a::**::b` matches `a::b` as well as `a::x::b`. A single `*`/`?` is unaffected.
- **`internal_template_leaks_via_public_api` no longer fires on a purely additive instantiation set.** The detector compared old vs. new instantiation sets with `!=` and reported any difference — including a template that only gained new instantiations, with every previously existing one still exported unchanged. An addition alone cannot break an already-linked consumer; the detector now only fires when at least one previously existing `(name, signature)` pair is missing from the new set.
- **`experimental_removed_without_replacement`'s reported leaf name no longer corrupts on a namespace-qualified parameter type.** For an ELF-only (no declared name) function, the detector fed the demangler's full declaration string — return type, qualified name, parameter list, and trailing qualifiers — straight into namespace-segment splitting, which only tracks `<`/`>` template-argument depth, not `(`/`)` parameter-list depth. A parameter type that was itself namespace-qualified (e.g. `ns::Type const&`) made the split land inside the parameter list, producing a leaf like `"data_type const&, long) const"` instead of the real member name. Now reuses `diff_templates._strip_param_signature` (already used by the CPO detector for the same reason) to strip the signature before segmenting.
