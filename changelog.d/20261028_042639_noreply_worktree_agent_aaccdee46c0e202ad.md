### Fixed

- **HTML and `--report-mode root-cause` stay bounded for non-gating findings** — a 5,000-addition run rendered about 1.2 MB of HTML and about 580 KB of root-cause Markdown, because both itemised one row per finding. Non-gating findings now share the Markdown size budget (25 rows per list), and the output states how many it cut. Gating findings are still itemised in full. The `--no-baseline` Markdown audit caps its candidate-side and suppressed tables the same way; its gate fires only on BREAKING/API_BREAK verdicts. JSON, SARIF and JUnit still carry every finding.
- **An acknowledged break accepted with `acknowledgment.breaks: accept` no longer counts as gating in the reports** — the severity block (`severity.exit_code`, `blocking`, SARIF's `exitCode`, the HTML gate card), the disposition ledger (`result_counts.gating`, the audit's `effective_total`) and the review groups (`gate_contribution`, the Markdown and digest gating lines) now agree with the process exit, which already excluded accepted breaks. A severity config that demotes an ABI break no longer lets an accepted API break re-enter the gate.
