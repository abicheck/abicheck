### Performance

- **A header-depth multi-library `compare` retains far less, on three independent counts, with identical results.** (1) Retention for JUnit and `--bundle-facts-out` is now resolved *per side and per consumer* (`workflows.release_snapshot_retention.SnapshotRetention`) instead of by one `need_full_snapshots` switch: both of those consumers read only the OLD side, so every member's full NEW `AbiSnapshot` — previously retained for the whole release and never opened — is now the compact `BundleSignatureEvidence` the bundle analysis already accepts. (2) `dumper_cache.AstAcquisitionScope` now bounds its *content-keyed* entries too (`MAX_RETAINED_RAW_ENTRIES`), whose `Future` results are the parsed AST roots themselves; only the `id()`-keyed groups were bounded before, so a measured six-member release held 24 raw roots while correctly reporting eight retained groups. A key every member shares is still acquired exactly once — the bound is an LRU, not a flush. (3) `--bundle-facts-out`'s JSON write streams (`storage.json_stream`, `snapshot_io.write_snapshot_text_stream`) rather than materialising every member's snapshot dict, the whole `indent=2` string and its UTF-8 encoding at once; the published bytes, digest and schema version are unchanged, checked differentially against the eager encoder.

### Added

- **`ABICHECK_MEMORY_TRACE` records an attributable memory trace** (`abicheck.workflows.memory_trace`): per phase, parent RSS, process-tree RSS *and* PSS, cgroup billing, and the structural counts that say what is resident (retained full snapshots per side, raw-AST groups and entries). Python allocation totals are a separate opt-in (`ABICHECK_MEMORY_TRACE_TRACEMALLOC`), never collected alongside a timing. Off by default and free when off. `scripts/bench_release_memory.py` builds a real compiled multi-library fixture and reports the same figures for a run, so a before/after pair is measured over one fixture by one harness.
