### Fixed

- **A stack canary that an optimized rebuild no longer needs is not reported as a hardening loss when debug info proves the flag unchanged** — an ELF dump now records every compilation unit's stack-protector setting from its `DW_AT_producer` (gcc records it by default, clang with `-grecord-command-line`). A `stack_canary_removed` finding is demoted to `COMPATIBLE` with rule `stack-protector-unchanged-in-every-unit` only when every unit on both sides records the protector, every exported function lies in one of those units, and no new unit is weaker than any old one. It keeps its RISK when the recorded flag was weakened or the builds mix settings, when a unit could not be read, when exported code comes from an object without debug info, and when no unit records the flag (binary only); in those cases `review_evidence.note` says why. Extractor generation 49; re-dump stored baselines to pick it up.
- **An exported object's alignment derived from its address no longer reads as a reduction by itself** — the address only bounds the declared alignment, so `exported_object_alignment_reduced` is demoted to `COMPATIBLE` (rules `address-alignment-without-declared-requirement`, `address-alignment-meets-declared-requirement`) unless the old side declares an alignment the new placement fails. The finding stays in the report. A dropped `_Alignas(16)` still reports under DWARF, whose `DW_AT_alignment` on a variable is now extracted, and under clang headers.
