### Added

- **`PUBLIC_VIRTUAL_DISPATCH_SET_CHANGED` flags a changed override set behind a stable public virtual** — when a public virtual method's possible runtime dispatch targets differ between two versions (an override was added or removed, as the source graph's approximate virtual-call join records them), `compare` now reports a `COMPATIBLE_WITH_RISK` source-graph finding naming the added and removed implementations. It is never a break on its own: the set is an over-approximation, so it is a risk to review, and it is compared as a set, so a reordered but unchanged override set is silent. The finding is emitted only when the call, override and virtual-dispatch passes ran to completion on both sides; a narrowed, degraded or unrecorded side produces no finding and no clean claim. Implemented in `compare/virtual_dispatch_set.py` and wired beside `diff_source_graph_findings` in `buildsource/evidence_report.py`. Covered by `catalog/cases/case219` (changed set) and its negative twin `case220` (reordered set), plus `tests/test_virtual_dispatch_set_findings.py`.
