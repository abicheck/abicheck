### Changed

- **10 more flat root modules given their ADR-061 responsibility-package classification** — `__main__.py` (`frontends` — trivial `cli.main` re-export), `aggregate.py`/`aggregate_findings.py`/`aggregate_manifest.py` (`workflows` — pure back-compat facades re-exporting from the already-`workflows`-owned `workflows/aggregate/*` package, same shape as `exit_decision.py`/`severity.py`/`contract_coverage_exit.py`'s existing `policy` classification), `api_types.py` (`workflows` — the Tier-2 service layer's typed request/response structs plus their own structural validation, ADR-037 D2/G22, a single coherent responsibility rather than two mixed ones), `config_paths.py` (`model` — a small, dependency-free `.abicheck.yml` candidate-location helper), `contract_gating.py` (`model` — pure predicate functions over `contract_relevance_types.py`'s already-`model` vocabulary, shared identically by `workflows`' `checker.py` and `policy`'s `severity.py`), `dumper_contract.py` (`extract` — ADR-050 D1 extraction-contract attachment, real but single-purpose extraction logic), `errors.py` (`model` — the exception hierarchy, no logic), `snapshot_cache.py` (`extract` — binary-analysis caching, matching this module's existing placement in this file's own module map right after `dumper.py`). Verified the same way as every classification in this PR: greedily tested against `check_architecture.check_repository()`'s full repo-wide import graph (`base_revision` pinned to the branch's merge-base with `main`, so the pre-existing `debt-no-growth` findings on unrelated large files don't pollute the count), keeping only additions that introduce zero new findings.

  This pass also re-surfaced, and re-rejected, the same greedy false positives this PR's earlier commits already found and reverted (`comparability.py` and its `comparability_fields.py`/`comparability_json.py`/`comparability_language_mode.py`/`comparability_sequences.py` family, `qualified_name_segments.py`, `dumper_manifest.py`, `product_baseline.py`, `stack_binding_diff.py`, `stable_abi.py`, `diff_versioning.py`) — the unconstrained greedy search happily proposes them again every time, since "introduces zero new findings under *some* layer" is a necessary but not sufficient condition; a module that is genuinely two responsibilities in one file can still mechanically pass under whichever layer's `may_import` set is broad enough to swallow both.

  New to this pass: `checker_policy.py`, `policy_file.py`, `reclassify.py`, and `contract_coverage_ledger.py` were tested specifically against their semantically-correct home (`policy` — verdict/severity/coverage-gating logic, matching this file's own "Policy & Suppression" section) rather than accepted at whichever layer the unconstrained search reached first. All four fail there outright (`checker_policy.py` alone introduces 129 new `dependency-direction` findings, because essentially every `compare`-layer detector imports it directly for `ChangeKind`/`Verdict`, and `compare` may not import `policy`) — confirming each is a real mixed-responsibility module (pure type/vocabulary content some other layer already depends on, bundled with real policy-decision logic) rather than a `policy`-owned one, so all four stay unclassified rather than being placed under whichever layer the naive search happened to reach first (which, left unconstrained, was `model`/`storage`/`workflows` respectively — equally wrong, just for a mechanical rather than a semantic reason). `build_context.py`, `deadline.py`, and `compatibility_evaluation_resolver.py` were investigated and left unclassified for the analogous reason: each mixes a real, non-trivial algorithm (compile-database parsing/response-file expansion; deadline-scoped subprocess-tree management; ADR-049 D7 field-precedence resolution) with content that only mechanically "fits" a layer because that module currently has few or no problematic imports — not because the layer is its true owner.

  No physical file moves, no runtime behavior change — `legacy_paths` entries only.
