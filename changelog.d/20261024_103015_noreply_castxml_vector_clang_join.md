### Fixed

- **castxml header comparisons see vector types** — castxml renders a vector as an opaque node with no element or lane count, so a same-size element change (`float` x8 to `int` x8) compared `NO_CHANGE` through `-H` headers. The clang AST of the same header now supplies the spelling (typedef, inline field, inline parameter), cached as a sidecar under the castxml key, and a missing or corrupt sidecar re-runs clang. castxml arrays also spell their element count correctly (`float[8]`, was `float[7]`).
