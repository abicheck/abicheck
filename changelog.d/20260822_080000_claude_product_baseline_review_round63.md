### Fixed

- **`pack_product_baseline()`'s decompressed-byte safety check is now exact, not an estimate.** The previous pack-time check summed only declared file content, omitting tar framing (a 512-byte header per member, data padded to a 512-byte boundary, the end-of-archive marker) -- the same framing `unpack_product_baseline()`'s own decompression-bomb defense counts as part of the raw decompressed stream. A pack could therefore succeed under a limit the reader would still reject the resulting archive against. Replaced with an exact, in-stream byte counter wrapping the same raw pre-compression tar stream the reader measures on decompression, so the two can never disagree.
- **`TarExtractor` now accounts for the worst-case disk-usage amplification a hard-linked archive member can cause on extraction.** A hard-link member's own declared size is `0` in tar format -- its data lives in the first-archived copy it references by name -- so the existing declared-byte-sum check never saw it. But `tarfile`'s own extraction machinery silently falls back to extracting a full, independent copy of the referenced member whenever `os.link()` fails (an unsupported filesystem, a cross-device link, ...), giving every alias its own distinct inode. An archive combining one large payload with many hard links to it could therefore amplify real disk usage (and subsequent checksum work) far beyond the declared-content ceiling. Now rejected up front, accounting for the worst case even across a chain of hard links.
- **`TarExtractor` now detects up front when the destination filesystem cannot create symlinks** (most notably Windows without `SeCreateSymbolicLinkPrivilege` -- no Developer Mode, not running elevated) and raises a clear, actionable error instead of silently letting `tarfile` substitute a full copy of the symlink's target. That silent substitution previously surfaced far downstream as a confusing "manifest never declared this file" error rather than an honest diagnosis of the real, platform-level cause.

### Fixed (test infrastructure)

- Fixed a genuinely platform-dependent test (`test_pack_preserves_executable_bit_set_only_for_group_or_other`) that had accidentally been asserting POSIX-only chmod semantics on Windows -- now skipped there, matching this suite's existing convention for POSIX-only file-mode tests.
- Fixed `test_pack_rejects_symlink_escaping_source_dir`'s symlink-target construction to use a literal forward-slash string instead of a `Path` join, whose `str()` rendering uses native (backslash) separators on Windows and could trip a different, also-real rejection reason first.
- Marked three fixture-only-constructible-on-POSIX tests (`test_pack_rejects_a_windows_drive_anchored_member_name`, `test_pack_rejects_a_backslash_traversal_member_name`, `test_pack_rejects_a_member_name_with_a_benign_backslash`) and three self-referential-symlink-loop tests (whose detection here relies on POSIX's `errno.ELOOP`, which Windows's own reparse-point loop handling doesn't reliably raise the same way) as Windows-skipped, matching this suite's existing platform-portability skip convention.
