### Fixed

- **`type_reachability.directly_referenced_stdlib_type_spellings`'s typedef-collision "same identity" exception no longer trusts a coincidental stripped-form match** (Codex review, fresh evidence). The exception exists to recognize a colliding typedef whose target genuinely names the very stdlib identity being evaluated (spelled fully qualified, or via a legitimate bare/partial form) rather than something else entirely — but the previous check compared both sides through `_stripped_signature_spelling`, which also strips inline ABI-tag namespaces (`__cxx11::`, `__1::`, `__ndk1::`). A typedef whose real target names a *different*, differently-ABI-tagged stdlib sibling the snapshot never captured (e.g. targeting `std::__cxx11::basic_string<char>` while only an unrelated, captured pre-C++11-ABI `std::basic_string<char>` exists) stripped-collapsed to the identical bare form purely by coincidence, and was waved through as "the same identity" — letting the captured record's derived bare spelling be exported (and, downstream, a layout finding on it confirmed) even though the typedef actually names something else. The exception now requires either an exact target match or a genuine structural namespace-suffix spelling of the identity itself (`_namespace_suffix_spellings`, which can only ever drop a scope-chain prefix the identity already carries and so cannot manufacture this ABI-tag coincidence).
