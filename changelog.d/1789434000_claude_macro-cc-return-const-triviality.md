### Fixed

- **Calling conventions spelled through macros** — the CastXML backend now reads a calling convention from the macro's compiler-resolved expansion (a `-E -dM` run of the same castxml command, cached with the AST), so `#define CALL __attribute__((ms_abi))` switching from `sysv_abi` is reported as `calling_convention_changed` instead of `NO_CHANGE`, and spelling the target's default convention explicitly (`sysv_abi` on x86-64 Linux) is no longer a change. The clang backend no longer reads clang's macro-qualified type spelling (`CALL int (int)`) as part of the return type, which reported a false `func_return_changed` when a literal attribute was replaced by an equivalent macro.
- **Return pointee qualifiers** — `char *f()` → `const char *f()` is now reported as `func_return_pointee_qualifier_added` (API break: `char *p = f();` stops compiling) instead of `NO_CHANGE`; the reverse direction is `func_return_pointee_qualifier_removed` (compatible with risk: only function-pointer consumers of the old type break).
- **Triviality without debug info** — the CastXML backend now derives `RecordType.is_trivially_copyable` from the special members it emits (proven true/false or unknown, never guessed), so a stripped library plus headers reports a struct gaining a user-provided destructor as `trivially_copyable_lost` (`BREAKING`), as the clang backend already did.
