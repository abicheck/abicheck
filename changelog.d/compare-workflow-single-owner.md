### Changed

- **One classification for every scalar `compare` route** — the native `compare` CLI now classifies a resolved pair through `workflows.compare_classify.classify_resolved_pair`, the same core the typed `CompareRequest` API and every release member run, instead of its own copy of depth projection, the evidence fold, `compare_snapshots`, the `--abi3`/`--depth` evidence-contract axes, operand metadata, requested depth, analysis assurance and evidence depths. Reports are unchanged except at the edges where the two copies had drifted: an out-of-band `--old/new-build-info`/`--sources` pack is now attached before `--depth` projection (as the typed route embeds one), and a `--budget` overrun during the evidence fold now exits 5 like one during classification instead of escaping as a traceback. The CLI-only seams are gone: `cli_resolve._resolve_compare_pair` returns the request with the pair, `workflows.depth_evidence_contract` and `compare_enrichment.report_depth_evidence_contract_error` were deleted (the core imports the `policy` owner directly), and tests that faked the CLI's classification now patch `workflows.compare_policy.compare_snapshots`.
