### Fixed

- **`TarExtractor`'s hard-link fallback-amplification check no longer trusts a stale regular-file-size entry once a later archive member reuses that name as a hard link.** The round-64 fix kept two separate maps -- one recording regular-file sizes, one recording hard-link targets -- and never evicted a name's stale entry in the first map when a later hard-link member reused that exact name (the same shape `tarfile.makelink()` extracts: the hard link overwrites the earlier regular file on disk). A subsequent alias of that name therefore still resolved against the small, stale regular-file size instead of the hard link's real, current worst-case size. Replaced both maps with a single, unconditionally-overwritten map of each name's fully-resolved worst-case size as of the latest member seen, so a later member can never resolve through an entry an intervening one should have replaced.
