### Performance

- **ELF symbol-table entries are now decoded with one bulk `struct.iter_unpack` instead of one `construct` parse per symbol.** `Elf_Sym` is a fixed-width, fixed-order record, but pyelftools' `SymbolTableSection.get_symbol` builds a parse tree and a `Container` per field for each one. Profiling the real hotspot made the split unambiguous: of the 13.58s a profiled `_pyelftools_exported_symbols` spent on oneDAL's `libonedal_core.so.3`, **12.87s was `get_symbol` and 11.9s of that was `construct`**, against essentially nothing for name resolution once the string-table buffer was applied. The new `extract/elf_symbol_fastpath.py` reads the table once and yields the four fields a filtering caller needs as plain integers, deliberately *not* rebuilding the `Symbol`/`Container` objects whose construction is the cost. Measured over oneDAL 2025.9.0's six-member release: **11.173s to 0.240s (46.5x)**, with byte-identical results on every member — `libonedal_dpc.so.3` alone goes from 7.221s to 0.105s.

  The fast path is scoped by refusal rather than by assumption: an unsupported ELF class or endianness, an `sh_entsize` disagreeing with the class's record size, a size that is not a whole multiple of it, a short or failed read, or a table past the allocation cap all return `None` and fall back to the ordinary reader, so malformed and unusual tables keep pyelftools' exact behaviour. Verified equivalent against the ordinary reader on **74 real shared objects across two oneDAL versions, with zero mismatches**, and against pyelftools' own parse for all four class/endianness combinations.

### Fixed

- **`st_other`'s visibility field is three bits wide, not two.** Found while building the fast path's oracle: pyelftools parses it as `BitField('visibility', 3)` so Solaris' `STV_EXPORTED`/`STV_SINGLETON`/`STV_ELIMINATE` (4/5/6) decode at all. Masking with `0x3` — which is what the generic ABI's two-bit description suggests — decodes `st_other == 5` (`STV_SINGLETON`, which the export filter keeps) as `1` (`STV_INTERNAL`, which it drops), silently removing a real export. The bug never reached a release: the exhaustive binding-by-visibility grid caught it before the decoder was wired up.
