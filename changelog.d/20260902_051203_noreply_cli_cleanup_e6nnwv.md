### Added

- **`BundleFacts` now carries an explicit `artifact_type` self-describing marker** (`abicheck.bundle-facts`, `BUNDLE_FACTS_SCHEMA_VERSION` bumped 1→2), and the G40 content-addressed archive container gets the same treatment (`abicheck.bundle-facts-archive`, required on read). CLI cleanup phase two, PR I prerequisite: a stored `BundleFacts` JSON document was previously identified only by `schema_version` plus the presence of a `per_library_snapshots` mapping, both too generic to key CLI operand classification on. A true v1 document — `schema_version` absent, or normalizing (matching the existing `int(...)` coercion, so `"1"`/`True` behave identically to the bare int `1`) to exactly `1` — with no `artifact_type` key stays fully readable, defaulting the same way `bundle_facts_from_dict` already defaults a missing `schema_version`, so an already-persisted baseline in a user's CI never needs regenerating; a document whose `schema_version` normalizes to `2`+ but omits the marker is rejected outright instead of silently defaulting, since schema_version 2 is exactly where the marker became mandatory (bypassing that would defeat the whole point of adding it); a document naming a *different* artifact type is rejected outright too. `bundle_facts_serialization.looks_like_bundle_facts_document()` is the new classifier a future unified `compare` operand dispatcher will use to detect a stored bundle-facts operand without a `--old-bundle-facts` mode flag — the `BundleCompareRequest` unification and the flag's removal remain blocked on PR G2's `GateOptions` object, which this PR does not introduce.
