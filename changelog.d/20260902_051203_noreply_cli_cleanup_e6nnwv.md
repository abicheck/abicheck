### Added

- **`BundleFacts` now carries an explicit `artifact_type` self-describing marker** (`abicheck.bundle-facts`, `BUNDLE_FACTS_SCHEMA_VERSION` bumped 1→2), and the G40 content-addressed archive container gets the same treatment (`abicheck.bundle-facts-archive`, required on read). CLI cleanup phase two, PR I prerequisite: a stored `BundleFacts` JSON document was previously identified only by `schema_version` plus the presence of a `per_library_snapshots` mapping, both too generic to key CLI operand classification on. A v1 document with no `artifact_type` key stays fully readable — `bundle_facts_from_dict` defaults a missing key the same way it already defaults a missing `schema_version` — so an already-persisted baseline in a user's CI never needs regenerating; a document naming a *different* artifact type is rejected outright. `bundle_facts_serialization.looks_like_bundle_facts_document()` is the new classifier a future unified `compare` operand dispatcher will use to detect a stored bundle-facts operand without a `--old-bundle-facts` mode flag — the `BundleCompareRequest` unification and the flag's removal remain blocked on PR G2's `GateOptions` object, which this PR does not introduce.
