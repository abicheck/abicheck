### Fixed

- **The whole-snapshot disk cache (`snapshot_cache.py`) is invalidated on
  upgrade to schema v28.** A warm cache entry written before the ADR-063
  Phase 2 `entity_id` carrier started persisting had `entity_id=None` for
  every declaration, and re-saving that loaded snapshot stamped it with
  the current `SCHEMA_VERSION` regardless of which version it was actually
  loaded from — so a stale entry could re-serialize claiming a genuine v28
  extraction that simply resolved no identities, rather than one that
  never had the chance to. `_SNAPSHOT_CACHE_VERSION` bumped to force
  re-extraction, the same precedent this cache's own `v21` bump already
  established for a comparable schema-version-tied fact.
