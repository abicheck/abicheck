### Changed

- **`--set` applies the compile-context keys, and the Action forwards them instead of writing a `compile:` file** — `compare --set` and `dump --set` now accept `compile.frontend`, `compile.frontend_context`, `compile.compiler`, `compile.options`, `compile.sysroot`, `compile.nostdinc`, `compile.std` and `compile.lang`, and resolve them through the same compile-context loader the `.abicheck.yml` `compile:` block uses, so `--set compile.K=V` and `compile: {K: V}` in the file give the same resolved context. Precedence is unchanged: flag > `--set` > file > default. `compile.include_dirs` and `compile.defines` stay on their core flags (`--include`, `--define`). The typed API still refuses these keys, because its requests do not fold a `.abicheck.yml` `compile:` block. The composite Action no longer synthesizes a temporary `compile:` config for `ast-frontend`, `gcc-path`, `gcc-prefix`, `gcc-options`, `sysroot`, `nostdinc` and `lang`. It forwards them as `--set compile.*`, and an explicit `set:` line is appended after them so it still wins. `set:` is now accepted in `mode: dump` as well as `mode: compare`. One behavior to check on upgrade: a `--sources` tree's own `compile:` block is now resolved by the CLI's own rules, not by the Action's earlier pairwise exclusion for a compare with an old side.
