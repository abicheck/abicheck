### Added

- **`ChangeKindRegistry` now validates policy-override references and
  default-verdict consistency during construction** (the production
  `REGISTRY` is built at import time, so this fires then in practice) —
  ADR-061 D9's "valid references" and "non-contradictory defaults"
  catalog-validation properties. A `ChangeKindMeta.policy_overrides` entry
  naming an unknown policy, targeting `strict_abi` (whose verdict is
  `default_verdict` itself), restating `default_verdict` verbatim, or
  declaring a non-`COMPATIBLE` verdict for `sdk_vendor`/`plugin_abi` (whose
  `policy_kind_sets()` implementation discards the declared verdict and
  always downgrades to `COMPATIBLE`) now raises `ValueError`, as does
  `is_addition=True` combined with a `default_verdict` other than
  `Verdict.COMPATIBLE`. A `ChangeKindMeta.description_template` referencing
  a placeholder outside `TEMPLATE_VOCAB` (`{symbol} {name} {old} {new}
  {detail}`) — including a bare positional `{}`/`{0}`, a field nested inside
  a format spec (e.g. `{name:{bogus}}`), an illegal `!conversion` specifier
  (only `!r`/`!s`/`!a`/none are legal for `str.format`), an invalid format
  *code* (e.g. `{name:q}`), or a format spec that fails for a real `None`
  value (`old`/`new`/`detail`/`name` are frequently `None` in practice), or
  field *traversal* (e.g. `{symbol[0]}`, `{symbol.__class__}`) — now raises
  the same way, instead of only failing the first time a finding of that
  kind is actually formatted. Validated by both a field-name check (exact
  `TEMPLATE_VOCAB` membership, catching traversal deterministically
  regardless of probe value) and actually executing `.format()` with
  representative values at construction time (catching everything a
  static parse can't predict — bad format codes, conversions,
  None-handling) — complementary, not redundant.
- **`ChangeKindMeta.policy_overrides` is now immutable after construction**:
  a `frozen=True` dataclass only stops reassigning the attribute, not
  mutating the dict object itself or a caller keeping a live reference to
  the dict it passed in — either could silently invalidate the
  reference/default checks already run at construction. Now defensively
  copied into an immutable mapping in `__post_init__` — not
  `types.MappingProxyType`, which cannot be pickled at all, and not a
  `dict` subclass either (an earlier iteration of this fix was one; a
  genuine `dict` instance's storage is still reachable through `dict`'s own
  *unbound* methods called directly — `dict.__setitem__(entry.
  policy_overrides, "unknown", Verdict.API_BREAK)` mutates the underlying
  hash table in C, with no Python-level override able to intercept a call
  to the base type's own descriptor). `_ImmutableDict` is instead a
  read-only `collections.abc.Mapping` implementation that stores its data
  privately, so `dict.__setitem__`/`dict.__or__` etc. reject it outright
  as not being a `dict` at all, and it still round-trips cleanly through
  `dataclasses.asdict()`/`copy.deepcopy()`/`pickle`, the same way an
  ordinary `dict` field does; the field's annotated type widened from
  `dict[str, Verdict]` to `Mapping[str, Verdict]` to reflect what callers
  actually receive. `entry.policy_overrides |= {...}` (PEP 584 in-place
  union) is blocked too — `Mapping` provides no `__or__`/`__ior__`, so
  Python's own operator resolution raises `TypeError` with no override
  needed. Re-invoking `__init__` directly
  (`entry.policy_overrides.__init__({...})`) on an already-constructed
  instance is explicitly guarded against, the same way. Being a non-`dict`
  `Mapping` meant `dataclasses.asdict()`'s generic branch (which reaches
  any non-dict/list/tuple/dataclass field via `copy.deepcopy()`) left an
  `_ImmutableDict` in the output — `json.dumps(asdict(entry))` raised
  `TypeError: Object of type _ImmutableDict is not JSON serializable`,
  where an ordinary dict field would have serialized fine. Fixed with a
  `__deepcopy__` override returning a plain, mutable `dict` — the
  disconnected copy `asdict()`/`copy.deepcopy()` produce is now ordinary
  and JSON-serializable, matching an ordinary dict field exactly, while the
  *original* entry's `policy_overrides` stays immutable regardless.
  Pickling is unaffected (a different mechanism, `__reduce__`) and keeps
  reconstructing a genuinely immutable copy, since its job is faithfully
  reconstructing the same object/type rather than producing
  JSON-primitive-friendly output. A remaining reflection-level gap: "no
  public mutator" only protects the `Mapping` interface, not the private
  `_data` attribute one attribute-access away —
  `entry.policy_overrides._data["unknown"] = ...` (or reassigning `_data`/
  `_initialized` wholesale) still mutated it. Fixed by storing `_data` as a
  `types.MappingProxyType` (so item assignment on it also raises) and
  overriding `__setattr__` to reject any attribute write once construction
  has completed.
- **The registry's core types and validation logic moved to their ADR-061
  target owner**: `Verdict`, `ChangeKindMeta`, `ChangeKindRegistry`,
  `VALID_BASE_POLICIES`, and `TEMPLATE_VOCAB` now live in a new
  `abicheck/model/change_catalog/registry.py` (D9's named destination for
  this logic; its `__init__.py` declares `__all__` per `abicheck/model/
  AGENTS.md`'s re-export-list contract). `change_registry_types.py` is now
  a pure compatibility re-export shim, and `checker_policy.py`/
  `diff_helpers.py` import `VALID_BASE_POLICIES`/`TEMPLATE_VOCAB` directly
  from the new location. Every existing import path (`from
  abicheck.change_registry_types import Verdict`, `from
  abicheck.change_registry import Verdict`, `from abicheck.checker_policy
  import VALID_BASE_POLICIES`) keeps working unchanged.
- **`ChangeKindRegistry` now enforces ADR-061 D9's fourth and final
  catalog-validation property, "complete metadata"**: every entry must
  carry non-empty `impact` text (`description_template` stays genuinely
  optional). Closed by writing 48 new, individually-accurate one-line
  impact descriptions for the entries that previously had none — real
  domain content, not a mechanical check — so all 397 `ChangeKindMeta`
  entries now describe concretely what happens and why. 38 of them moved
  to a new sibling file, `abicheck/change_registry_parity.py` (following
  the same size-relief-split pattern `change_registry_composition.py`/
  `_coverage.py`/etc. already establish), since `change_registry.py` was
  exactly at its 2000-line adoption-debt ceiling; the other 10 (the
  `[[deprecated]]`-transition kinds) already lived in
  `change_registry_castxml.py`, which had headroom. The emptiness check is
  whitespace-aware (`impact.strip()`) so `impact="   \n"` is rejected too,
  not just the literal empty string.
