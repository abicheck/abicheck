### Changed

- **The root Action's baseline selection is now exclusive, and its `project_ref` is checked by default** — when `baseline-profile` and `baseline-target` are both set, `action/run.sh` resolves the baseline from the release-contract baseline-set archive alone. It no longer downloads the single `*.abicheck.json` asset first, so a stray legacy asset can neither replace the selected baseline nor fail the job with "Multiple *.abicheck.json assets found". A missing archive fails the run and names it. With the selection unset, the single-snapshot-first contract is unchanged. The new `baseline-project-ref` input (default `tag`, the resolved release tag) is checked against the archive's manifest `project_ref`. **Migration:** a baseline-set whose `project_ref` is not the release tag — one captured elsewhere, which records a commit — now fails with `outcome: wrong_project_ref`. Set `baseline-project-ref: commit` (the commit the tag names, annotated tags peeled), pass a full commit SHA, or set `''` to keep the previous unchecked behaviour. The run also records which baseline it compared against, in a "Baseline source" step-summary block and in the new `baseline-source`, `baseline-asset-name`, `baseline-project-ref`, `baseline-generation` and `baseline-profile` outputs.
