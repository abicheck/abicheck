### Added

- **`aggregate` folds ADR-049's contract-coverage axis** (`aggregate_schema_version` 1.3). Each target's own `contract_coverage_exit_contribution` is read from its report — never recomputed, so a target run under `contract.unresolved=warn` keeps its acceptance — and folded with `max` into the aggregate exit code, the same way `compare` and `scan --against` already fold theirs. Without it a matrix could exit `0` while a target in it exited `1` for incomplete contract evidence, the cross-command divergence ADR-049 §6.4 forbids. Reported as its own `contract_coverage` block rather than inside `coverage`, since "did every required target report?" and "could a reporting target close its contract domain?" are different questions that both contribute `1`. A report carrying no such key contributes `0`, so existing matrices are unchanged.

  The keys are read from all three real report shapes, outermost first: a `compare` report's root, `ScanOutcome.to_dict()`'s `diff` block (what `scan --against` writes), and `ScanResult.to_dict()`'s `report.diff` (the public envelope `service_scan.run_scan` returns). An inner value is a fallback for an unusable outer one, never an override of a valid one. A malformed contribution takes the documented fail-open path — including a boolean, which `raw not in (0, 1)` would have accepted since `True == 1` in Python, letting it beat a perfectly good nested value.

  A target that *accepted* incomplete coverage is still listed in `incomplete_targets`: failure presence is tracked separately from the exit contribution, because `contract.unresolved=warn` zeroes the floor and changes nothing else. Accepting incomplete assurance is not hiding it (§6.2).
