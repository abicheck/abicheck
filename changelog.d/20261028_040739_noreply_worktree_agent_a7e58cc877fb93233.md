### Fixed

- **Callers of the platform parsers no longer read an unread export table as an empty one.** The dump already refuses a binary whose export table could not be read, but other callers took the parser's empty result for "exports nothing". `debian_symbols.generate_from_binary` and `validate_from_binary` and `post_manifest.validate_from_binary` now raise the dump's error instead of producing an empty symbols file or reporting every declared symbol missing. `bundle.build_bundle_snapshot` refuses such a member instead of dropping it from the bundle graph. The dependency resolver behind `deps tree`, `deps compare`, `dump --follow-deps` and `compare --follow-deps` refuses an unreadable DSO, so its symbols no longer read as missing; the `deps` commands exit 1 with that error line. The package-claim check reports that it was not performed rather than a fabricated mismatch, and `resolve-baseline` names the unread table. A stranded library's `--bundle-facts-out` snapshot persists its export table as unread, not as an empty readable one.
