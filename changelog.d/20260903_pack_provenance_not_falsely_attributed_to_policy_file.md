### Fixed

- **A `CompareRequest` carrying `pack_policy_overrides`/`pack_internal_namespaces` (the directory/package release fan-out's own mechanism) could persist a receipt that falsely attributed a pack's overrides to `policy_file_path`.** `classify_compare_pair` folds a resolved pack's contributions into the loaded `PolicyFile` for scoring, but that merged object cannot say which of its `overrides` came from the file and which from a pack — passing it to the gate-receipt installer misattributed the pack's own override as file-sourced, with the file's real digest covering content it never actually contained. The receipt installer now receives the `PolicyFile` as loaded, before pack folding, so it records only what the file itself stated. The release fan-out (today's only caller of these two fields) is unaffected — it already overwrites this receipt with its own correctly-provenanced one immediately after (`cli_compare_receipt.record_release_resolved_config`); this closes the gap for a direct typed-API caller that doesn't.
