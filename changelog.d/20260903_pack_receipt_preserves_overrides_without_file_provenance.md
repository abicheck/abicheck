### Fixed

- **A typed `CompareRequest(pack_policy_overrides=..., contract_evaluation=True)` request could persist a receipt whose `effective_config_digest` didn't reflect the pack's contribution at all.** The previous fix for `policy_file_path` misattribution passed the receipt installer the *pre-fold* `PolicyFile`, which stopped the false attribution but also meant the pack's own override never appeared in the receipt — two otherwise-identical requests differing only in `pack_policy_overrides` could render the same digest despite scoring to different verdicts (`BREAKING` vs. `COMPATIBLE`). `pack_application.policy_file_with_packs` now clears the merged `PolicyFile`'s `source_path`/`source_sha256` whenever it actually folds pack content in — on top of a real loaded file, not only when synthesizing one from scratch — so the receipt keeps the pack's contribution (the digest changes with it) without claiming it came from `policy_file_path`.
