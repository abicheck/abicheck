### Fixed

- **A changed value on a C++17 inline variable or an out-of-line const is reported** — `inline int x = 1;` in a header made the whole header parse fail as C, so both frontends dropped its value and a `1` to `2` change compared as `NO_CHANGE`. Such a header is now parsed as C++. A non-const `inline` arithmetic header variable's initializer is recorded as its value on both frontends (pointers, classes and non-inline globals still carry none), and a `const` integral global the header only declares (`extern const int k;`, or a class's `static const int k;` defined in a `.cpp`) takes its value from the exported object's bytes. Extractor generation 30; a baseline from an earlier generation is re-dumped, not compared against the new value. A variable template under the castxml frontend is still not seen (see `known-gaps.md`).
