### Fixed

- Under a stated public contract (`scope: public: true`), `imported_symbol_added`/`imported_symbol_removed` findings are now `NOT_APPLICABLE` to the contract by kind, like `needed_*` and `symbol_version_required_*` already were, so policy still scores them (a `strict` preset still gates them), and runtime-owned symbols that no ELF table lists (leaked-dependency, std:: binding-strengthening findings) get `toolchain_runtime_origin` consistently. An ordinary rebuild with libstdc++ drift no longer exits 1 on unsuppressible `finding_unresolved` contract-coverage failures; the findings stay in the report.
- Markdown "Related review groups" counted a member's raw breaking verdict as a gate contribution, so findings proven out of contract (JSON `gate_contribution: 0`) read as "N gating finding(s)". It now counts only evaluated findings. A mangled function-local static no longer files its family under `(undemangled)`.
- The Markdown "Contract Source Conflicts" section is now bounded: a count per conflict kind and origin, at most 20 itemised rows with clipped names (library entities first), and a pointer to JSON `contract_conflicts` for the full list. On a C++ library it was 355 KB on a byte-identical rebuild.
