### Fixed

- **`TarExtractor` now bounds a PAX/GNU extended-header record's declared size before `tarfile` reads it into memory.** `tarfile.TarInfo._proc_pax()`/`_proc_gnulong()` each read a PAX ('x'/'g') or GNU longname/longlink ('L'/'K') extended-header record's entire declared byte length in one call, before ever returning control to a caller iterating the archive -- so this module's own streaming, member-by-member size checks never got a chance to intervene before that allocation already happened. An uncompressed archive with a single oversized extended-header record was accepted regardless of the overall decoded-bytes limit, and a trivially small, highly compressible `.tar.zst` could force the same allocation through decompression. Every `tarfile.open()` call in this module now uses a `TarInfo` subclass that pre-screens an extended header's declared size, taken straight from its own 512-byte header block, against a dedicated (env-overridable) safety limit before `tarfile`'s own parsing ever reads it -- rejecting the archive outright rather than materializing an oversized record first. Ordinary long paths/linknames, which real archives use routinely and which this limit is generous relative to, are unaffected.
