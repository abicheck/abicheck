### Added

- **Class-template parameter defaults are recorded, and a header-level default change is an `API_BREAK`** (ADR-085) — the clang header backend now records each class template pattern's per-parameter default spelling as `RecordType.template_param_defaults_fact` (snapshot schema v62; a pre-v62 snapshot reads it as not recorded, never as "no defaults"). A header-only change to such a default now reports the new `TEMPLATE_PARAM_DEFAULT_CHANGED` kind (`API_BREAK`, `HEADER_OR_SOURCE_GATED`) instead of `NO_CHANGE`. An exported instantiation that already reports `DEFAULT_TEMPLATE_ARG_CHANGED` (`BREAKING`) keeps that finding alone, and the suppressed header-level relation is recorded in the disposition ledger. A template pattern whose defaults are not recorded now lowers `analysis_assurance` to `partial` instead of reading as a clean comparison. castxml cannot record the defaults, so a castxml run scans the public headers it parsed for one (snapshot schema v63, `template_default_header_scan`). When the scan finds a template default the run reads `partial` with the note `template-parameter defaults (castxml cannot record them)`; the castxml verdict stays `NO_CHANGE` for this shape. A clang run over a class template with a non-type or template-template parameter also reports the `partial` assurance status, because its defaults are not recorded for that template.
