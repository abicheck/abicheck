### Fixed

- **Hardened `type_reachability.directly_referenced_stdlib_type_spellings`'s ambiguity guard with real per-identity match provenance** — an earlier version dropped a whole group of stdlib identities sharing an ambiguous namespace-stripped bare spelling even when one member was separately, unambiguously confirmable via its own fully-qualified spelling elsewhere in the same snapshot. `type_reachability._StdlibReferenceScan` now tracks, alongside its flat `referenced()` set, which identities were matched via their own literal, un-derived spelling (`referenced_exact()`), and — separately — which were matched only while recursively resolving a typedef alias, keyed by which top-level alias led there (`referenced_exact_typedef_aliases()`), so a genuinely unambiguous route still confirms an identity independent of an unrelated collision on its derived spelling. Exact-match provenance is now snapshot-order-independent (the scan runs to completion via a new `full_scan` mode instead of stopping early once every stdlib candidate is accounted for via *some* route), and collision counting spans every stdlib identity the snapshot carries, not only the referenced subset.
- **Closed three more collision routes in the same ambiguity guard**: an unrelated `snapshot.enums` member (not just `snapshot.types` records) sharing a stdlib identity's stripped bare spelling now correctly counts as a collision; an unrelated `snapshot.typedefs` key — or one of its own derived namespace-suffix spellings, resolved or left ambiguous — sharing that spelling is now checked too (`type_reachability._typedef_candidate_spellings`); and a typedef whose *resolved* target genuinely names the identity being evaluated (spelled fully qualified, or in some other stdlib-namespaced shape reducing to the same bare form) is correctly no longer treated as a collision at all.
- **Added an optional `committed_roots` allowlist to `directly_referenced_stdlib_type_spellings`**, mirroring `compare --post-manifest`'s own scoping: a manifest-scoped run demotes any *export* finding whose symbol isn't in the committed allowlist, but this function's own scan previously seeded from every still-`PUBLIC`, header-committed declaration regardless — an uncommitted-by-manifest function whose signature happened to mention a stdlib template type could still confirm an unrelated dependency-layout finding as `IN_CONTRACT`/`COMPLETE`. `contract_pipeline.build_contract_stage` now threads its own `committed_exports` allowlist through.
