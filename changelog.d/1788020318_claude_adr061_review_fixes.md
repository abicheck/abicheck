### Fixed

- **`strip_vendor_hash` no longer mis-strips a hyphenated hex run from a non-library filename** — `_VENDOR_HASH_RE`'s numeric-version lookahead branch (`\.\d`, meant for a version segment genuinely sitting between the vendor hash and a `.so`/`.dylib` extension) matched *any* numeric continuation regardless of what followed, so e.g. `strip_vendor_hash("plugin-abcdef.1.json")` silently produced `"plugin.1.json"` even though the input isn't a shared-library name at all (CodeRabbit review, PR #942, pre-existing bug — not introduced by this PR's `binary_naming.py` split, just found while reviewing the moved code). Tightened the lookahead to require the numeric segment(s) to still be followed by a real `.so`/`.dylib` suffix. `tests/test_vendor_hash.py` gains a regression test targeting the bug class (several sibling non-library shapes, not just the one reported input) alongside a sibling test pinning the real, intended multi-component-version case the branch exists for.

### Changed

- **Two ADR-061 classifications from earlier commits on this PR reverted after review** — `qualified_name_segments.py` (classified `model`) and `dumper_manifest.py` (classified `extract`) are each genuinely mixed modules, not single-responsibility ones: `qualified_name_segments.py` combines pure name/segment helpers with `renumber_anonymous_closure_identities()`/`defer_closure_identity_renumbering()`, which mutate a fully-populated snapshot in place and manage thread-local extraction sequencing — operational behavior, not shared naming vocabulary; `dumper_manifest.py`'s `_run_tu_fragments()`/`run_tu_loop()`/`resolve_header_ast_result()` own worker-pool lifetime, deadline propagation, and failure-cancellation sequencing atop the manifest-vs-legacy dump-flow decision, not just extraction primitives (Codex review, PR #942). Both reverted to unclassified rather than split in this pass, consistent with `stable_abi.py`/`comparability.py`'s own same-shaped reversions earlier in this PR. Neither revert breaks anything already classified: nothing currently `legacy_paths`-classified strictly needed either target to resolve to a specific layer rather than `None`.
