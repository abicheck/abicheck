# P5: `mandatory_template_param_added` (and other API_BREAK kinds) reported at binary depth without header evidence

Repository: `/home/user/abicheck`, HEAD `026a6109e`. Analysis only; no repo files were modified.
Read first: `AGENTS.md`, `docs/contribute/known-gaps.md`.

## Summary

- The reported finding is real at the verdict level. A binary-only comparison with no headers
  yields `verdict = API_BREAK` when only `mandatory_template_param_added` is injected, and a
  constructed 10-stem binary-only case reproduces the reported shape exactly: 10 x
  `mandatory_template_param_added` plus 10 x `inline_function_removed`, verdict `API_BREAK`.
- Root cause: the binary-depth publicness signal for this detector is **binary export**
  (`public_functions` -> `is_abi_visible`), but the kind it emits is a **source-level**
  break (`API_BREAK_KINDS`). Nothing between detection and verdict asks for **producer-observed
  contract evidence** (header set supplied, subject declared in it). For API_BREAK kinds, the
  verdict is decided by registry membership alone (`compute_verdict`, `policy/classification.py:506`).
- Premise correction: I did not find a public-surface *demotion* that export-removal kinds apply
  without headers. The export-removal kinds (`func_removed`, `var_removed`,
  `func_removed_elf_only`) are `BREAKING` and stay `BREAKING` with no headers, because the binary
  export is artifact proof of a consumer-visible break. The only header-gated demotion,
  `FilterNonPublicSurface`, is a no-op without a resolvable header surface. Export-removal kinds
  instead pick their kind by linkage evidence (`_check_removed_function`).
- Bug class: two other API_BREAK kinds reach `API_BREAK` verdict from binary-depth or DWARF-only
  input with no header evidence (`type_removed`, `inline_function_removed`; verified with isolated
  verdicts). Two more (`experimental_removed_without_replacement`, `unspecified_return_now_named`)
  set `public_reachable=True` from export/name evidence at detector level, not isolated at verdict
  level. `std_reexport_removed` and `tag_type_renamed` hard-code `public_reachable=True` on
  paths I did not reach. Of the 53 API_BREAK
  kinds, 11 are Python-axis, 1 is a sentinel, and the rest are header/source/build-gated or
  DWARF/header type-level kinds that I did not probe.
- Recommendation: one central policy step (default-deny for binary-producible API_BREAK kinds,
  keyed on producer-observed contract evidence, demoting to `COMPATIBLE_WITH_RISK` with a
  recorded disposition), plus removal of the hard-coded `public_reachable=True` claims. This is a
  behaviour change (exit 2 becomes a lower exit for header-less runs) and needs an ADR per
  `AGENTS.md`. Test plan in section 5.

## 2. Root cause

1. **Wrong evidence axis for the claim.** Binary export (`binary_exported`, fact c) proves a
   consumer can link to the instantiation. It does not prove that the template's arity is a
   source contract. `is_public` at `diff_templates.py:1004/1016` is set from binary export via
   `public_functions`/`is_abi_visible`. The source-level claim needs fact (b),
   `in_public_contract`, which is only *observed* when a public-header set was supplied.
   `surface_facts.py:199-205` shows the legacy bridge: `PUBLIC` visibility yields a *partial* (b)
   with `DERIVED_FROM_LEGACY`. That is not an observation.
2. **Self-asserted tag.** `public_reachable=True` / `PROVEN_REACHABLE` /
   `direct_public_symbol` is set at construction (`diff_templates.py:1053`) from the same export
   population. The tag is circular: it cannot gate the kind that set it.
3. **Verdict depends only on kind.** `compute_verdict` maps API_BREAK_KINDS to `API_BREAK`
   regardless of tags or evidence (`classification.py:506-548`). No pipeline step consults
   contract evidence for API_BREAK kinds.
4. **The only gate is header-conditional.** `FilterNonPublicSurface` and
   `classify_change_surface` fall back to "keep everything" without resolvable headers
   (`post_processing.py:379-384`, `surface.py:636-637`). Correct conservatively, but that means
   the no-header path has no publicness gate at all for source-level kinds.
5. **"Internal" was inferred from absence.** The user's premise is that the entity is internal
   because it is in a `backend` namespace and in no header. `backend` is not in
   `DEFAULT_INTERNAL_NAMESPACES`, so the namespace rule cannot apply. At binary depth the header
   set is unknown, so (b) is *unknown*, not "not public". The correct reading is
   "contract not established", which should narrow the conclusion (weaker evidence narrows
   conclusions; AGENTS "Product decisions").

Why `mandatory_template_param_added` is the visible symptom: it is the one API_BREAK kind whose
detector is *name-based* (template arity from demangled spelling) and whose population is the
binary-export population. A binary-only run therefore produces it routinely.

## 4. Proposed fix

### 4.1 Options

**(A) Per-detector fixes.** Change `diff_templates.py:1004/1016/1035` so `is_public` requires
`has_observed_contract_evidence` on some contributing declaration. Change `diff_symbols.py:246`
so `INLINE_FUNCTION_REMOVED` requires observed (b). Restrict `type_removed` population to
observed (b). Drop the hard-coded `public_reachable=True` at `diff_templates.py:1160`,
`namespace_shape_detectors.py:174` and `diff_cpp_patterns.py:529`. Re-derive the
`subject_is_public` flag at `diff_namespaces.py:977/996` from observed (b) rather than export.

- Pros: precise; each change is local; no behaviour change for header-backed runs.
- Cons: about 8 touch points; no mechanism stops the next detector from repeating the mistake.
  This is the same failure mode as the `_PUBLIC_SOURCE_ABI_KINDS` "public by construction" comment
  and as the existing hard-coded `public_reachable=True` sites. It treats the instance, not the class.

**(B) Central policy gate (recommended).** A new step in `policy/finding_disposition/` placed
after `MarkReachability` / before `ApplySuppression`. For each finding whose kind is in
`API_BREAK_KINDS` and is marked binary-producible in the registry:

1. Resolve the subject (`symbol`) in old and new declarations.
2. Keep as API_BREAK if `has_observed_contract_evidence(subject)` holds on either side
   (`model/surface_facts.py:294`). This is producer-observed (b), not legacy-derived (b),
   and not `in_public_surface` (which falls back to binary export, the trap noted at
   `surface_facts.py` `is_public_export`).
3. Otherwise demote to `COMPATIBLE_WITH_RISK` through the per-finding effective verdict. Record
   the disposition per ADR-067: rule id (for example `source_break_without_contract_evidence`),
   reason ("no observed public-contract evidence: no public-header set"), original kind and
   verdict. The finding stays in `diff.changes` and the report; nothing is dropped.
4. Default-deny for a binary-producible kind with no resolvable subject. Do not default-keep, because
   binary-producible producers must always have a subject.
5. Exempt: `evidence_required_missing` (sentinel), `python_api_*` (own evidence axis, gated by
   the `.pyi` surface instead), and kinds explicitly bucketed as GATED-BY-CONSTRUCTION
   (their producers already require header/source/build evidence).

The gate must not read `public_reachable` / `reachability_kind` as evidence. Those are set from
the same export population (circular), and they are absent in default runs.

**(C) Linkage-based classification alone.** Choosing a binary or source kind by linkage is a
classification choice, not a source-contract proof. `known-gaps.md` records this exact shape as a
"Do not re-attempt" item: demoting vanished weak/vague-linkage exports by `is_inline` or COMDAT
was reverted twice (`known-gaps/linkage-blind-removal-attempted-twice-reverted-twice-the.md`,
with the `extern template` counterexample). Do not use linkage as a proxy for source contract.

### 4.2 Recommendation

Do (B) as the enforcement point and (A)'s hard-coded-claim removals as cleanup. (B) is the only
option with a completeness property (section 5). (A) alone leaves the class open. (C) is not a
proof of source contract.

### 4.3 Costs and governance

- Behaviour change: header-less runs that today report `API_BREAK` (exit 2) would report
  `COMPATIBLE_WITH_RISK`. `AGENTS.md` says a default, exit code, or public interface change needs
  its ADR and migration. Write an ADR (for example, extend ADR-067 or ADR-044 D1) and a changelog
  fragment via `scriv create`.
- Evidence label: `evidence_status_for_change` is a pure function of kind, and per-finding
  overrides are deliberately not trusted for labels. A demoted finding would still read
  `source_contract` unless a per-finding status is added (for example, mirroring the existing
  `UNATTRIBUTED` downgrade in `evidence_status_for_result`). Choose one; do not hide the demotion.
- Registry: the "binary-producible" bucket must live in the taxonomy (`model/change_catalog/`) or
  a `policy/` table with the same exactly-one-bucket enforcement as section 5, not an ad hoc set.

## 5. Testing

### 5.1 Why it was missed

1. Detector-level tests only. `tests/test_diff_templates.py:1002-1040` calls
   `detect_mandatory_template_param_added` directly and asserts kind and symbol. Nothing asserts
   the verdict, and nothing asserts `public_reachable` for the function-stem path.
2. Verdict-level property tests use headers throughout. `tests/test_surface_evidence_asymmetry_properties.py`
   (around lines 686-750) builds snapshots with `from_headers=True` and `in_public_contract_fact`
   on every declaration. The binary-only case is never generated.
3. Negative tests assert the fallback as correct. `tests/test_finding_disposition_pipeline.py`
   covers `scope_fell_back` as "keep everything" (correct for scoping), not as "API_BREAK
   without contract evidence is a gap".
4. Completeness tests classify, not behave. `tests/test_changekind_completeness.py:477` lists which
   test file exercises each kind (`MANDATORY_TEMPLATE_PARAM_ADDED` is listed under
   `test_kde_compat_detectors.py`). It does not run a binary-only fixture.
5. The one binary-only mandatory test, `tests/test_rust_cdylib_integration.py:181`, asserts the
   kind is *absent* for a Rust arity-parser bug. It does not test publicness.
6. The "public by construction" assumption (`_PUBLIC_SOURCE_ABI_KINDS`) was reasoned about, not
